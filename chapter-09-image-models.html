09Image Models(图像模型)

LLM 不只看文字,还能"看"图片。ImageModel 生成图(DALL·E 类),ImageContent 喂图给 LLM(gpt-4o vision 类)。本章讲 LangChain4j 抽象的图像能力全集(基础篇收官章)。

一句话定性:LangChain4j 把图像能力分两类:① 图像生成(ImageModel,DALL·E / 通义万相)② 图像理解(ImageContent 配合支持视觉的 ChatModel,gpt-4o / qwen-vl)。

1. 业务场景

老板:"我们 AI 客服要能看图。用户发来一张破损商品的照片,要能识别破损程度 + 触发售后流程。"

这就是多模态视觉问答(Visual QA)。LLM 不直接处理像素,但支持视觉的模型能把图转成"我看到的"自然语言,LLM 再按自然语言推理。

3 个真实场景

  • 电商售后看图 — 用户发破损商品图,AI 识别 + 触发退款
  • AI 海报生成 — "给我画一张春节促销海报" → DALL·E 输出
  • 商品图理解 — 上传商品图,自动生成标题 / 描述 / 标签

3. 能力 ①:图像生成(ImageModel)

OpenAI DALL·E 3 案例 — 文字描述生成图片:

ImageModel imageModel = OpenAiImageModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("dall-e-3")
        .size("1024x1024")
        .quality("hd")
        .build();

Response<Image> response = imageModel.generate("A white cat sitting on a red sofa, oil painting style");

Image image = response.content();
String base64Data = image.base64Data();
String mimeType   = image.mimeType();   // "image/png"
String revisedPrompt = response.revisedPrompt();   // DALL·E 实际用的 prompt

4. 能力 ②:图像理解(ImageContent)

把图片 + 文字一起发给支持视觉的 ChatModel(gpt-4o / qwen-vl / glm-4v):

ChatModel visionModel = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o")             // ⭐ 要视觉模型
        .build();

// 方式 1:网络 URL
ImageContent image = ImageContent.from("https://example.com/damaged-product.jpg");

// 方式 2:本地文件 → Base64
byte[] bytes = Files.readAllBytes(Paths.get("broken.jpg"));
String base64 = Base64.getEncoder().encodeToString(bytes);
ImageContent image = ImageContent.from(base64, "image/jpeg");

// 提问
UserMessage msg = UserMessage.from(
    TextContent.from("这张图里商品破损程度如何?需要退款吗?"),
    image
);
ChatResponse resp = visionModel.chat(msg);
System.out.println(resp.aiMessage().text());

5. 多模态实战:破损商品售后

完整业务场景 —— 用户上传图,AI 识别 + 触发流程:

interface DamageAssessor {
    @UserMessage("""
        你是电商售后 AI。请根据用户上传的商品图片判断:
        1. 破损等级(SEVERE 重度 / MODERATE 中度 / MINOR 轻微 / NONE 无)
        2. 是否建议全额退款(true/false)
        3. 简要原因(一句话)
        """)
    DamageReport assessDamage(@V("image") ImageContent image);
}

record DamageReport(
    DamageLevel level,
    boolean fullRefund,
    String reason
) {}

enum DamageLevel { SEVERE, MODERATE, MINOR, NONE }

// 配置模型要支持视觉 + JSON Schema
DamageAssessor assessor = AiServices.builder(DamageAssessor.class)
        .chatModel(visionModel)              // gpt-4o
        .supportedCapabilities(RESPONSE_FORMAT_JSON_SCHEMA)
        .strictJsonSchema(true)
        .build();

6. 5 种 Content 类型(回顾 ch01)

LangChain4j 不只支持图片,完整多模态体系:

  • TextContent — 文本(最常用)
  • ImageContent — 图片(URL / Base64)
  • AudioContent — 音频(部分厂商支持)
  • VideoContent — 视频(类似 ImageContent 的二进制包装)
  • PdfFileContent — PDF 二进制

8. 避坑指南

坑 1 · 模型名不区分 = 视觉能力直接消失

同样 "gpt-4o" 和 "gpt-4o-mini",前者有视觉,后者部分场景视觉弱。国产 qwen2.5 不带 "-vl" 后缀就不看图。调用前确认模型支持视觉(看厂商文档的"vision / multimodal"列)。

坑 2 · 大图不压缩 = 烧光 token

用户发 10MB 原图,你直接喂给 LLM = 模型按图像 token 计费,可能几千 token 就为了一张图。先压缩到 1024px 长边 + JPEG 80%,既够模型看清又省 token。

坑 3 · URL 图片 = LLM 服务要去 fetch

ImageContent.from("https://...") 内部会让 LLM 服务去下载图。如果 LLM 服务在境外 / 有防火墙 / URL 限流,会失败或超时。生产永远用 Base64 嵌入(预下载 + 转码)。

坑 4 · DALL·E 3 自动改写 prompt

response.revisedPrompt() 返回的"实际用的 prompt"跟你给的"原始 prompt"经常不一样(DALL·E 内部会改写以提高质量)。不要在审计日志里只存原始 prompt,两者都存。

坑 5 · 图片理解 ≠ 精确 OCR

LLM 看图能"理解大致内容",但对小字 / 表格 / 数字识别准确率不如专业 OCR(百度 / 腾讯 / PaddleOCR)。如果业务是"提取图里身份证号",先 OCR 拿文字再喂 LLM 更靠谱。
