04 流式传输(Token 级别边生成边推)

AsyncGenerator 嵌入 + StreamingChatGenerator + SpringStreamingChatGenerator + SSE / WebSocket · 6 业务场景

一句话定性:流式传输 = LLM Token 边生成边推给用户。LangGraph4j 基于 java-async-generator 库,流式图输出(.stream())+ 节点内子流(AsyncGenerator 嵌入)+ 2 套 LLM 流式生成器(LangChain4j / Spring AI)。

核心价值:用户体验从"等 5 秒看完整段"变成"打字机效果",首字 200ms 出;agent 多步循环时,用户看到每步进度,不焦虑。

1. 业务场景

老板:"咱们的 AI 客服是'一次返回完整答案',用户等 5 秒看不到东西,以为卡了 → 刷新 → 重复请求。怎么办?"

解法:用 流式传输 —— LLM 每个 Token 一出来就推给前端(SSE / WebSocket),用户 200ms 看到第一个字,边看边等。LangGraph4j 用 StreamingChatGenerator 把 LangChain4j / Spring AI 的 streaming model 适配成 AsyncGenerator,节点返回 generator 实现"子流"。

6 个流式传输能解决的事

  • ⌨️ 打字机效果 — 用户 200ms 看到首字,体验比"等 5 秒"高 10 倍
  • 🔄 Agent 多步进度 — "思考中 → 调工具:查订单 → 调工具:查库存 → 整理答案",用户看到每步,不等焦虑
  • 🛑 早停 + 节省 Token — 用户看到一半觉得答案不对,点"停",后面 30% Token 不生成(只付生成部分的)
  • 📊 实时反馈埋点 — 每 Token 推一次,前端埋点能算"实际展示率"(用户有没有真看到完)
  • 🧪 流式 debug — 复杂 agent 出问题,看"哪个 Token 错了 / 哪步错了",而不是看完整 500 字找
  • 🔌 多端适配 — Web 用 SSE(单向,简单)/ App 用 WebSocket(双向)/ CLI 用 stdout 实时打印

💡 什么时候不需要:批量离线任务(发邮件 / 生成报表)/ 内部 ETL 流水线 / 用户场景是"点提交等结果"(不是"边看边等") —— 流式反而增加复杂度。流式是"用户实时交互 + 节省感知时间"的优化方案。

口诀:流式 = LLM Token 边生成边推。3 步:1. 节点返回 AsyncGenerator(不是 String)+ 2. StreamingChatGenerator 适配(LangChain4j / Spring AI 各一套)+ 3. 主图 .stream() 遍历。配合 lg03 并行 = 实时 + 高性能双 buff。

3. .stream() 流式图输出(基础)

LangGraph4j 内置 graph.stream() 流式输出(对应 lg01 提过):

var generator = graph.stream(inputs, config);

// AsyncGenerator 必须迭代才能触发
for (var step : generator) {
    System.out.println("执行: " + step);  // NodeOutput(nodeId, state)
}

// 拿最终结果
var finalResult = GraphResult.from(generator);

注意:.stream() 本身不是 Token 级 —— 它返回每节点的执行结果。如果节点内是 LLM,LLM 是一次性返回的(没流式)。

真正 Token 级需要节点内子流(下面)。

4. AsyncGenerator 嵌入(子流核心)

LangGraph4j 的杀手锏 —— 节点可以返回 AsyncGenerator(不是 Map),主图的迭代器会暂停,先消费完子 generator,再恢复主迭代。

// 普通节点返回 Map
AsyncNodeAction<State> normalNode = state -> Map.of("key", "value");

// 流式节点返回 AsyncGenerator(新!)
AsyncNodeAction<State> streamingNode = state -> {
    // 返回 generator(不是 Map)—— 主图会自动"嵌入"
    return someAsyncGenerator;
};

3 步行为:

  1. 主图跑到 streamingNode,看到返回是 AsyncGenerator(不是 Map)
  2. 主图迭代器暂停,先消费 someAsyncGenerator 全部元素
  3. 子 generator 跑完,主图继续下一节点

好处:用户感知不到"嵌套",从 graph.stream() 看是扁平的事件流。

5. LangChain4j 流式(node-by-node → Token 级)

5.1 LangChain4j 原生 streaming

// LangChain4j streaming model
StreamingChatLanguageModel model = OpenAiStreamingChatModel.builder()
    .apiKey(System.getenv("OPENAI_API_KEY"))
    .modelName("gpt-4o-mini")
    .build();

// onNext 每个 Token 触发
model.generate("Tell me a joke", new StreamingResponseHandler<AiMessage>() {
    public void onNext(String token) {  // ← 每个 token 一次
        System.out.print(token);
    }
    public void onComplete(Response<AiMessage> response) { /* ... */ }
    public void onError(Throwable error) { /* ... */ }
});

5.2 StreamingChatGenerator(适配器)

LangGraph4j 提供 StreamingChatGenerator 把 StreamingResponseHandler 转换 AsyncGenerator:

var generator = StreamingChatGenerator.builder()
    .mapResult(r -> Map.of("content", r.content()))   // 把完成结果转 Map(给 State)
    .build();

model.generate("Tell me a joke", generator.handler());  // ← 用 generator 的 handler

for (var step : generator) {              // ← 遍历 generator(每个 Token 一次)
    log.info("{}", step);
}

log.info("RESULT: {}", GraphResult.from(generator));

关键 3 参数:

  • mapResult:必填,Function<Response<AiMessage>, Map<String,Object>>,流完成时调,把 Response 转 Map(LangGraph4j 期望的 State 更新格式)
  • startingNode(可选):流开始的节点 ID
  • startingState(可选):流开始的 State

5.3 节点里返回 generator(完整示例)

Map<String, Object> callAgent(State state) {
    // 1. mapResult:把 Response 转 Map
    final Function<Response<AiMessage>, Map<String, Object>> mapResult = response -> {
        if (response.finishReason() == FinishReason.TOOL_EXECUTION) {
            // LLM 决定调工具
            var toolReqs = response.content().toolExecutionRequests();
            var action = new AgentAction(toolReqs.get(0), "");
            return Map.of("agent_outcome", new AgentOutcome(action, null));
        } else {
            // LLM 给出最终答案
            var result = response.content().text();
            var finish = new AgentFinish(Map.of("returnValues", result), result);
            return Map.of("agent_outcome", new AgentOutcome(null, finish));
        }
    };

    // 2. 建 generator
    var generator = StreamingChatGenerator.<AiMessage, State>builder()
        .mapResult(mapResult)
        .startingNode("agent")
        .startingState(state)
        .build();

    // 3. 用 streaming 调 LLM(异步,不等)
    streamingChatLanguageModel.generate(messages, tools, generator.handler());

    // 4. ⚠️ 关键:节点返回 generator(不是 Map)
    return Map.of("agent_outcome", generator);
}

行为:

  • streamingChatLanguageModel.generate(...) 异步开始(不阻塞)
  • 节点立刻返回 Map.of("agent_outcome", generator)
  • 主图看到 generator 嵌入,暂停主迭代,先消费 generator
  • 每个 Token 一出来,generator emit 一次,主图 forward 一次 → 前端拿到每个 Token
  • LLM 完成(返回 Response),mapResult 转 Map,generator 完成
  • 主图恢复,继续下一节点

6. Spring AI 流式

Spring AI 的 streaming 返回 Flux<ChatResponse>(Reactive),需要 SpringStreamingChatGenerator 适配:

6.1 Spring AI 原生 streaming

var chatClient = ChatClient.builder(chatModel)
    .defaultSystem("You are a helpful AI Assistant answering questions.")
    .build();

Flux<ChatResponse> flux = chatClient.prompt()
    .messages(new UserMessage("tell me a joke"))
    .stream()
    .chatResponse();

6.2 SpringStreamingChatGenerator

// 适配 Flux → AsyncGenerator
var generator = SpringStreamingChatGenerator.builder()
    .startingNode("agent")
    .mapResult(response -> Map.of(
        "messages", response.getResult().getOutput()
    ))
    .build(flux);   // ← 喂 Flux

for (var step : generator) {
    log.info("{}", step);
}

6.3 节点里用 Spring AI + SpringStreamingChatGenerator

Map<String, Object> callAgent(State state) {
    // 1. Spring AI 调 streaming
    Flux<ChatResponse> flux = chatClient.prompt()
        .messages(state.messages())
        .stream()
        .chatResponse();

    // 2. 适配成 AsyncGenerator
    var generator = SpringStreamingChatGenerator.<State>builder()
        .startingNode("agent")
        .startingState(state)
        .mapResult(response -> Map.of(
            "messages", response.getResult().getOutput()
        ))
        .build(flux);

    // 3. 返回 generator
    return Map.of("messages", generator);
}

同 LangChain4j 模式:节点返回 generator,主图嵌入消费。

8. 实战:流式 AI 客服(多 Agent)

用户问 → 路由 → 选 Agent → 流式输出:

// === 1. 路由节点(不流式) ===
AsyncNodeAction<State> router = state -> {
    String userMsg = (String) state.value("userMessage").orElse("");
    // 简单分类(实际可用 LLM 分类)
    if (userMsg.contains("订单") || userMsg.contains("order")) {
        return Map.of("nextAgent", "order");
    } else if (userMsg.contains("物流") || userMsg.contains("shipping")) {
        return Map.of("nextAgent", "shipping");
    } else {
        return Map.of("nextAgent", "general");
    }
};

// === 2. 订单 Agent(流式) ===
AsyncNodeAction<State> orderAgent = state -> {
    String userMsg = (String) state.value("userMessage").orElse("");

    // LangChain4j streaming
    var generator = StreamingChatGenerator.<AiMessage, State>builder()
        .mapResult(resp -> Map.of(
            "messages", resp.content().text(),       // 累积到 messages
            "agentOutcome", "finished"
        ))
        .startingNode("order_agent")
        .startingState(state)
        .build();

    streamingChatModel.generate(
        List.of(UserMessage.from(userMsg)),
        generator.handler()
    );

    return Map.of("__stream__", generator);   // 标记为流式
};

// === 3. 物流 Agent / 通用 Agent 类似(略) ===

// === 4. 主图 ===
var customerService = new StateGraph<>(State.SCHEMA, State::new)
    .addNode("router", router)
    .addNode("order_agent", orderAgent)
    .addNode("shipping_agent", shippingAgent)  // 类似 orderAgent
    .addNode("general_agent", generalAgent)    // 类似 orderAgent
    .addNode("format_reply", state ->
        Map.of("reply", formatAsString(state.value("messages").orElse(List.of()))))

    .addEdge(START, "router")
    .addConditionalEdges("router",
        edge_async(state -> (String) state.value("nextAgent").orElse("general")),
        EdgeMappings.builder()
            .to("order_agent", "order")
            .to("shipping_agent", "shipping")
            .to("general_agent", "general")
            .build())
    .addEdge("order_agent",    "format_reply")
    .addEdge("shipping_agent", "format_reply")
    .addEdge("general_agent",  "format_reply")
    .addEdge("format_reply", END)
    .compile();

// === 5. SSE 推给前端 ===
@GetMapping(value = "/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> chat(@RequestParam String message) {
    var generator = customerService.stream(
        Map.of("userMessage", message),
        RunnableConfig.builder().threadId("user-1").build()
    );

    // AsyncGenerator → Flux<ServerSentEvent>
    return Flux.create(sink -> {
        generator.forEachAsync(step -> {
            // 每个 step 推一次
            sink.next(ServerSentEvent.builder()
                .event("step")
                .data(step.toString())
                .build());
        }).thenRun(sink::complete)
          .exceptionally(sink::error);
    });
}

前端:

// JavaScript:EventSource
const es = new EventSource('/chat/stream?message=查订单');
es.addEventListener('step', e => {
    console.log('Token 来了:', e.data);
    // 追加到页面

es.addEventListener('done', e => es.close());

用户体验:

  • t=0:用户发"查订单 ORD-001"
  • t=200ms:前端看到"正在调订单接口..."
  • t=400ms:前端看到"正在查物流..."
  • t=500ms-3s:LLM 边生成边推,前端逐字显示"您的订单 ORD-001 状态:已发货,顺丰单号 SF12345..."
  • t=3s:流完成,前端关闭 EventSource

9. 配合 lg03 并行(高级模式)

并行 + 流式 = 实时 + 高性能双 buff:

// 3 个 Agent 并行跑(各流式)
var concurrentStreaming = new StateGraph<>(State.SCHEMA, State::new)
    .addNode("dispatch", state -> Map.of("prompt", state.value("question").orElse("")))
    .addNode("agent1", state -> {
        var g = makeStreamingAgent("agent1", state);  // 各自流式
        return Map.of("__stream_1__", g);
    })
    .addNode("agent2", state -> {
        var g = makeStreamingAgent("agent2", state);
        return Map.of("__stream_2__", g);
    })
    .addNode("agent3", state -> {
        var g = makeStreamingAgent("agent3", state);
        return Map.of("__stream_3__", g);
    })
    .addNode("merge", state -> {
        // 3 路结果合并
        return Map.of("final", mergeAll(state));
    })
    .addEdge(START, "dispatch")
    .addEdge("dispatch", "agent1")
    .addEdge("dispatch", "agent2")
    .addEdge("dispatch", "agent3")
    .addEdge("agent1", "merge")
    .addEdge("agent2", "merge")
    .addEdge("agent3", "merge")
    .addEdge("merge", END)
    .compile();

// 跑
concurrentStreaming.stream(
    Map.of("question", "..."),
    RunnableConfig.builder()
        .addParallelNodeExecutor("dispatch", ForkJoinPool.commonPool())  // 并行
        .build()
);
// 前端同时收到 3 路 Token(混合显示 / 分别显示各路)

注意:并行流式时,3 路 Token 顺序不确定(谁先 emit 谁先到)。前端要能区分各路(用 key prefix / ID)。

10. 决策树(用流式吗?)

11. 5 个避坑

⚠️ 坑 1:把 graph.stream() 当成 Token 级流
症状:graph.stream() 出来 3 步(node by node),以为是 Token 级,实际只是节点级。
根因:graph.stream() 是节点级(每节点一个 step),不是 Token 级。
修法:Token 级 = 节点内返回 AsyncGenerator(StreamingChatGenerator / SpringStreamingChatGenerator),主图嵌入消费。
⚠️ 坑 2:流式节点忘返回 generator,变一次性
症状:调 streaming model,但节点返回 Map.of("text", fullText)(一次性),用户还是等 5 秒看完整段。
根因:节点必须返回 Map.of("k", generator)(generator 作 value),主图才识别为"嵌入"。
修法:
  • streaming model → async 调用(handler 不阻塞)
  • 节点 return Map.of("k", generator) 而不是 Map.of("k", fullText)
  • mapResult 在流完成时才被调(把 Response 转 Map)
⚠️ 坑 3:并行流式 3 路 Token 顺序错乱
症状:3 个 Agent 并行流式,前端收到 Token 顺序:A1_token, B1_token, A2_token, B2_token(交替),不是 A1→A2→A3 / B1→B2→B3 各路有序。
根因:并行执行,3 路谁先 emit 谁先到(调度不确定)。
修法:
  • 前端:用 key prefix / ID 区分各路(step.agentId),自己排序
  • 后端:SSE event 加 id 字段(Agent ID)
  • 或:非并行流式(代价是 wall-clock 长)
⚠️ 坑 4:流式 + 检查点回放,Token 重复 / 漏
症状:用 MemorySaver 中断恢复,流式时已 emit 的 Token 和 resume 后的 Token 拼起来有重复 / 缺失。
根因:流是"中间状态",检查点存的是"完整状态" —— 中断前已 emit 的 Token 没持久化,resume 后重新 emit。
修法:
  • 流式不用检查点(检查点设计为"完整任务重跑",不适合"Token 级回放")
  • 真要 resume,前端记录已收到的 Token,resume 后去重(用 Token index)
  • 或:把流结果落库(检查点存"已 emit 列表"),resume 时跳过
⚠️ 坑 5:流式 SSE 没设超时,长 LLM 卡死
症状:LLM 推理 60 秒才出第一个 Token,前端 SSE 默认 30 秒超时,断连后用户看不到结果。
根因:SSE / WebSocket 默认有代理超时(Nginx 60s / Tomcat 30s 等),长 LLM 可能超时。
修法: 
// 1. 服务端:先发心跳("ping")告诉代理"我没卡"
@GetMapping(value = "/chat/stream", produces = TEXT_EVENT_STREAM_VALUE)
public Flux<String> chat(...) {
    return Flux.interval(Duration.ofSeconds(15))   // 15s 一次心跳
        .map(t -> ":\n\n")                          // SSE 注释行
        .mergeWith(actualStream);
}

// 2. 反向代理:Nginx 加 proxy_read_timeout 600s 等
// 3. 前端:EventSource 自带重连,断了自动重连
// 4. 服务:把"已开始"先写 DB,断了前端刷新能拿到

13. 本章小结

  • 3 层概念:AsyncGenerator 库 + 节点返回 generator(嵌入)+ 2 套 LLM 适配器
  • 关键 3 步:节点用 streaming model → 节点返回 Map.of("k", generator) → 主图嵌入消费
  • 2 套适配器:LangChain4j(StreamingChatGenerator)/ Spring AI(SpringStreamingChatGenerator)
  • mapResult 必填:把 Response/ChatResponse 转 Map(流完成时调)
  • 前端协议:SSE(单向,简单)/ WebSocket(双向,实时)/ stdout(CLI)
  • 6 大场景:打字机 / Agent 进度 / 早停 / 埋点 / debug / 多端
  • 配合 lg03 并行:并行 + 流式双 buff(注意 Token 顺序)
一句话总结:LangGraph4j 流式 = "AsyncGenerator 嵌入 + 2 套 LLM 适配器"。节点返回 generator 而不是 String/Map,主图自动"子流"消费。下一章(lg05 钩子)在节点前后加拦截器(日志 / 监控 / 鉴权)。
