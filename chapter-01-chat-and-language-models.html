01Chat and Language Models

LangChain4j 调用大模型的最底层入口。ChatModel 接口 + 9 个 chat(...) 方法签名 + 5 种 Content 多模态,搞懂它,后面所有高级 API 都不再神秘。

一句话定性:ChatModel 是 LangChain4j 一切 LLM 调用的起点。其它所有 API(AI Services / Tools / Streaming)最终都委托给它。先学它最扎实。

1. 业务场景

想象你是一个电商 Java 后端,老板说:"接入一个 AI 客服,用户问'我买的那双鞋什么时候发货',机器自动查订单 + 调 OpenAI 回答"。

第一步不是写 Agent 也不是搞 RAG,而是 —— 先把一句话发给 LLM,拿到字符串回答。这一步就要用到 ChatModel。

常见 3 个使用场景

  • AI 客服回复 — 用户问一句,模型答一句,直接展示给用户
  • 文本分类 / 情感分析 — "这条评论是正向还是负向" → 单次 chat() 调用
  • 提示词工程实验场 — 想快速试不同 prompt 效果,直接 chat("translate this to French: ...")

2. 核心概念

LangChain4j 把不同厂商的 LLM 能力抽象成几个统一接口。最低层两个:

  • LanguageModel — 最原始的"输入字符串、输出字符串"。LangChain4j 已不再扩展,新代码不要再用。
  • ChatModel — 支持结构化 ChatMessage(用户/AI/系统/工具消息),支持多模态。⭐ 官方主推,所有新功能基于它。

围绕 ChatModel 还有 4 个旁系接口,LangChain4j 都已实现统一适配:

  • EmbeddingModel — 文本转向量(给 RAG 用)
  • ImageModel — 图像生成(DALL·E 类)
  • ScoringModel — 重排序(RAG 精排)
  • ModerationModel — 内容审核

3. 极简调用(3 行代码)

OpenAI 厂商的 ChatModel 创建 + 调用,最短形态:

// 1. 用 Builder 模式构造 ChatModel
ChatModel model = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o-mini")
        .build();

// 2. 最简形态:输入字符串,返回字符串
String answer = model.chat("Translate to French: hello world");
System.out.println(answer);  // → "Bonjour le monde"

4. 9 个 chat 方法签名(API 全貌)

官方 ChatModel 接口提供的 9 个 chat(...) 重载,按"输入形态"分 4 类:

类 1:字符串入参(最简)

String chat(String userMessage);

直接把字符串当成 UserMessage,适合演示 / 一次性 prompt。

类 2:多 ChatMessage 入参(对话历史)

ChatResponse chat(ChatMessage... messages);
ChatResponse chat(List<ChatMessage> messages);

传多个 ChatMessage(用户 + 系统 + AI 历史),返回 ChatResponse(含元数据)。

类 3:ChatRequest 入参(完整控制)

ChatResponse chat(ChatRequest request);
ChatRequest ChatRequest.builder()
        .messages(List.of(new UserMessage("Hello")))
        .temperature(0.7)
        .build();

类 4:Kotlin 协程(异步)

// Kotlin DSL:类型安全构建器
suspend fun askAI(prompt: String): String =
    model.chat {
        messages += UserMessage(prompt)
        temperature = 0.7
    }

5. ChatMessage 4 种类型

ChatMessage 是消息的接口,4 个实现类:

类型作用常见场景
UserMessage用户发的消息用户问的"什么时候发货?"
AiMessageAI 返回的消息对话历史里塞 AI 上次回答
SystemMessage系统提示词"你是一个 Java 专家,只回答 Java 问题"
ToolExecutionResultMessage工具调用结果Tools 章详细讲

6. Content 多模态(5 种)

每条消息可以带多种内容,不只是文字。官方支持的 5 种 Content:

  • TextContent — 普通文本(最常用)
  • ImageContent — 图片(支持 URL 或 Base64),用于多模态视觉问答
  • AudioContent — 音频(部分厂商支持)
  • VideoContent — 视频(类似 ImageContent 的二进制包装)
  • PdfFileContent — PDF 二进制
UserMessage msg = UserMessage.from(
    TextContent.from("这张图里有什么?"),
    ImageContent.from("https://example.com/cat.jpg")
);
ChatResponse resp = model.chat(msg);

7. 避坑指南

坑 1 · 不要再用 LanguageModel

LangChain4j 官方明确:已停止扩展 LanguageModel。所有新功能只加在 ChatModel。新项目直接用 ChatModel,避免选型失败。

坑 2 · API Key 必须读环境变量,不要硬编码

示例代码 System.getenv("OPENAI_API_KEY") 是硬规范。硬编码到源码 = 上 GitHub 后 5 分钟被盗刷,几千元账单一晚。

坑 3 · String chat(String) 不支持 system 消息

这个最简重载只把字符串当成 UserMessage。如果你想加系统提示词,必须用 chat(List<ChatMessage>) 或 chat(ChatRequest)。

坑 4 · 多模态图片不是所有厂商都支持

ImageContent 要传到支持视觉的模型(gpt-4o / qwen-vl / glm-4v),纯文本模型直接抛异常。先看模型名后缀有没有 -vl / -vision。

坑 5 · chat() 阻塞,长 prompt 别放主线程

单次 chat() 默认是同步阻塞,3-10 秒返回正常。Java Web 项目里一定要用 @Async 或丢线程池,否则接口超时。
