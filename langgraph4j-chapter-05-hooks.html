05 钩子(节点/边前后拦截器)

NodeHook × EdgeHook × 3 类型(Before / After / Wrap)× 全局 + ID 特定双注册 · 6 业务场景

一句话定性:钩子 = 在节点/条件边执行前后插入自定义代码的拦截器。LangGraph4j 提供 NodeHook / EdgeHook 双接口,每个接口 3 个时机(BeforeCall / AfterCall / WrapCall),支持全局 + ID 特定双注册,LIFO(Before/After)/ FIFO(Wrap)不同执行顺序。

核心价值:业务核心逻辑保持"纯净"(只关注业务),日志 / 监控 / 鉴权 / 重试 / 限流 / 脱敏 / 缓存 这些"横切关注点"全部下沉到钩子里。一图顶千言:

1. 业务场景

老板:"咱们的 graph 跑起来黑盒 —— 谁调了哪个 node、耗时多少、报错在哪?出问题时只能看日志猜。"

解法:用 钩子 —— 在节点/边执行的"前后 / 包裹"位置插入横切代码,业务核心保持纯净,所有"运维关注点"统一收口到 hook。

6 个钩子能解决的事

  • 📋 执行日志 + 链路追踪 — 每个节点耗时 + 入参出参,问题定位从"翻日志猜"到"看 span 直接定位"
  • 📊 Prometheus / Micrometer 埋点 — 节点级 QPS / P99 延迟 / 错误率,接入告警系统
  • 🔐 鉴权 / 越权检查 — "调 delete_order 节点前,检查用户角色是 admin",普通用户直接抛异常短路
  • 🔁 重试 / 限流 / 熔断 — 调外部 API 失败自动重试 3 次;QPS 超阈值直接抛 RateLimitExceededException
  • 🛡️ 数据脱敏 / PII 检测 — 输出写到日志 / 推到前端前,身份证 / 手机号 / 邮箱自动脱敏为 ***
  • 🗄️ 结果缓存 / 短路返回 — 同一入参命中缓存,直接返回缓存值,不调原 node(用 WrapCall 实现)

💡 什么时候不需要:简单 demo / 一次性脚本 / 单节点 graph(没有多节点横切需求)/ 已经用 AspectJ / Spring AOP 在更上层统一拦截(避免重复)。

2. 核心概念

2.1 双接口 × 三时机矩阵

接口时机用途返回
NodeHook.BeforeCall节点执行前日志 / 鉴权 / 参数校验Map<String,Object>(注入到 state)
NodeHook.AfterCall节点执行后埋点 / 缓存写入 / 异常捕获Map<String,Object>(注入到 state)
NodeHook.WrapCall完整包裹限流 / 重试 / 缓存短路Map<String,Object>(完全控制)
EdgeHook.BeforeCall边执行前条件边的参数校验Command
EdgeHook.AfterCall边执行后路由结果审计Command
EdgeHook.WrapCall完整包裹条件边的缓存 / 重试Command

2.2 双注册方式(全局 + ID 特定)

2.3 执行顺序:Before/After LIFO vs Wrap FIFO

⚠️ 顺序坑:同一节点注册多个 hook 时:BeforeCall 和 AfterCall 走 LIFO(后注册先执行,像 try/finally 反过来);WrapCall 走 FIFO(先注册先包裹,像洋葱层)。混用时先 Wrap 再 Before/After,记不住就画洋葱图。

3. 极简调用(3 行注册全局日志钩子)

最小可运行 demo,注册一个全局 BeforeCall,所有节点执行前打印入参:

import org.bsc.langgraph4j.hook.NodeHook;
import org.bsc.langgraph4j.RunnableConfig;

NodeHook.BeforeCall<State> loggingHook = (nodeId, state, config) -> {
    System.out.println("[BEFORE] node=" + nodeId + " input=" + state);
    return CompletableFuture.completedFuture(Map.of()); // 空 map = 不注入新 state
};

var graph = new StateGraph(State::new)
    .addNode("process", processNode)
    .addBeforeCallNodeHook(loggingHook)   // ← 一行注册全局钩子
    .addEdge(START, "process")
    .addEdge("process", END)
    .compile();

跑起来,每次进入 process 节点都会先打印 [BEFORE] node=process input=...。业务代码一行没改。

4. NodeHook 3 类型实战

4.1 BeforeCall:全局日志 + 链路追踪 ID 注入

// 全局 BeforeCall:每个节点执行前注入 traceId + 打日志
NodeHook.BeforeCall<State> traceHook = (nodeId, state, config) -> {
    String traceId = config.threadId().orElse(UUID.randomUUID().toString());
    System.out.printf("[%s] → node=%s, state=%s%n", traceId, nodeId, state);
    // 把 traceId 注入 state,后续节点可读取
    return CompletableFuture.completedFuture(Map.of("_traceId", traceId));
};

var graph = new StateGraph(State::new)
    .addNode("step1", step1Node)
    .addNode("step2", step2Node)
    .addBeforeCallNodeHook(traceHook)  // ← 全局注册
    .addEdge(START, "step1")
    .addEdge("step1", "step2")
    .addEdge("step2", END)
    .compile();

4.2 AfterCall:Prometheus 埋点 + 异常捕获

// 全局 AfterCall:节点执行后上报耗时
NodeHook.AfterCall<State> metricsHook = (nodeId, state, config, lastResult) -> {
    long startNs = (long) state.value("_nodeStartNs").orElse(System.nanoTime());
    long elapsedMs = (System.nanoTime() - startNs) / 1_000_000;
    metricsRegistry.counter("graph.node.invoke", "node", nodeId).increment();
    metricsRegistry.histogram("graph.node.latency", "node", nodeId)
                   .record(elapsedMs, TimeUnit.MILLISECONDS);
    System.out.printf("[METRIC] node=%s 耗时=%dms%n", nodeId, elapsedMs);
    return CompletableFuture.completedFuture(Map.of());
};

// 在 BeforeCall 里同时记录开始时间
NodeHook.BeforeCall<State> startTimeHook = (nodeId, state, config) -> {
    return CompletableFuture.completedFuture(
        Map.of("_nodeStartNs", System.nanoTime())
    );
};

var graph = new StateGraph(State::new)
    .addBeforeCallNodeHook(startTimeHook)   // ← 先记录开始时间
    .addAfterCallNodeHook(metricsHook)      // ← 再上报耗时
    .addNode("a", aNode)
    .addNode("b", bNode)
    .addEdge(START, "a")
    .addEdge("a", "b")
    .addEdge("b", END)
    .compile();

4.3 WrapCall:缓存短路 + 重试

// WrapCall:同一入参命中缓存,直接返回缓存值,不调原节点
NodeHook.WrapCall<State> cacheWrapHook = (nodeId, state, config, action) -> {
    String key = nodeId + ":" + state.input().orElse("");
    if (cache.containsKey(key)) {
        System.out.println("[CACHE HIT] " + key);
        return CompletableFuture.completedFuture(cache.get(key));  // ← 短路,action 不执行
    }
    return action.apply(nodeId, state, config)   // ← 调原 action
        .thenApply(result -> {
            cache.put(key, result);
            return result;
        });
};

var graph = new StateGraph(State::new)
    .addWrapCallNodeHook(cacheWrapHook)   // ← 包裹式拦截
    .addNode("expensive", expensiveNode)
    .addEdge(START, "expensive")
    .addEdge("expensive", END)
    .compile();

5. EdgeHook:条件边的钩子

EdgeHook 只对条件边生效(普通 addEdge(src, dst) 静态边没有 hook 时机)。Edge 返回 Command(包含 next nodeId + state update),可以拦截路由决策。

// 场景:订单路由条件边 - 用户是 VIP 才走"快速通道"
EdgeHook.BeforeCall<State> routeAuditHook = (sourceId, state, config) -> {
    System.out.println("[ROUTE] 从 " + sourceId + " 出发, state=" + state);
    return CompletableFuture.completedFuture(null);  // 不修改路由
};

// ID 特定:只对 "decide_route" 这条边生效,其他条件边不受影响
var graph = new StateGraph(State::new)
    .addNode("check_user", checkUserNode)
    .addNode("fast_path", fastPathNode)
    .addNode("slow_path", slowPathNode)
    .addConditionalEdges("check_user",
        state -> state.isVip() ? "fast" : "slow",
        Map.of("fast", "fast_path", "slow", "slow_path"))
    .addBeforeCallEdgeHook("decide_route", routeAuditHook)  // ← 只对 decide_route 生效
    .addEdge(START, "check_user")
    .addEdge("fast_path", END)
    .addEdge("slow_path", END)
    .compile();

6. 实战:WMS 智能调度 + 钩子组合(6 业务场景落地)

跨境电商 WMS 系统,有这些横切关注点,全部用钩子收口:日志 + 鉴权 + 限流 + 重试 + 脱敏 + 缓存。

WMS 业务场景映射

业务场景钩子类型实现要点
📋 所有节点执行日志全局 BeforeCall打印 nodeId + traceId + 输入参数
🔐 危险节点鉴权ID 特定 BeforeCalldelete_order / manual_override 节点检查 user role
📊 Prometheus 埋点全局 AfterCallQPS / P99 / 错误率
🔁 外部 API 重试ID 特定 WrapCall调三方物流 API 失败重试 3 次
🛡️ PII 脱敏全局 AfterCallstate 里手机号/身份证 → 138****1234
🗄️ 调度结果缓存ID 特定 WrapCall同 SKU + 同仓库 5 分钟内不重复算

完整代码

// ============ 1. 全局日志钩子 ============
NodeHook.BeforeCall<WmsState> wmsLogHook = (nodeId, state, config) -> {
    String traceId = config.threadId().orElse("n/a");
    log.info("[WMS][{}] → node={}, input={}", traceId, nodeId, state.input());
    return CompletableFuture.completedFuture(Map.of("_traceId", traceId));
};

// ============ 2. 危险节点鉴权(ID 特定) ============
NodeHook.BeforeCall<WmsState> adminOnlyHook = (nodeId, state, config) -> {
    String userRole = state.userRole().orElse("guest");
    if (!"admin".equals(userRole)) {
        throw new SecurityException("节点 " + nodeId + " 需要 admin 权限,当前: " + userRole);
    }
    return CompletableFuture.completedFuture(Map.of());
};

// ============ 3. Prometheus 埋点(全局 AfterCall) ============
NodeHook.AfterCall<WmsState> metricsHook = (nodeId, state, config, lastResult) -> {
    long start = (long) state.value("_nodeStartNs").orElse(System.nanoTime());
    long elapsed = (System.nanoTime() - start) / 1_000_000;
    Counter.builder("wms_node_invoke_total").tag("node", nodeId).register(registry).increment();
    Timer.builder("wms_node_latency_ms").tag("node", nodeId).register(registry)
         .record(elapsed, TimeUnit.MILLISECONDS);
    return CompletableFuture.completedFuture(Map.of());
};

// ============ 4. 外部 API 重试(ID 特定 WrapCall) ============
NodeHook.WrapCall<WmsState> carrierApiRetryHook = (nodeId, state, config, action) -> {
    int maxRetry = 3;
    for (int i = 0; i < maxRetry; i++) {
        try {
            return action.apply(nodeId, state, config);
        } catch (Exception e) {
            if (i == maxRetry - 1) throw new RuntimeException("调用承运商 API 失败", e);
            try { Thread.sleep(1000L * (i + 1)); } catch (InterruptedException ie) { Thread.currentThread().interrupt(); }
            log.warn("[WMS] {} 第 {} 次重试", nodeId, i + 1);
        }
    }
    return CompletableFuture.completedFuture(Map.of());
};

// ============ 5. PII 脱敏(全局 AfterCall) ============
NodeHook.AfterCall<WmsState> piiMaskHook = (nodeId, state, config, lastResult) -> {
    Map<String, Object> masked = new HashMap<>(lastResult);
    masked.replaceAll((k, v) -> v instanceof String s ? maskPii(s) : v);
    return CompletableFuture.completedFuture(masked);
};
private static String maskPii(String s) {
    return s.replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2")  // 手机号
            .replaceAll("(\\d{4})\\d{10}(\\w{4})", "$1**********$2"); // 身份证
}

// ============ 6. 调度结果缓存(ID 特定 WrapCall) ============
LoadingCache<String, Map<String, Object>> scheduleCache = Caffeine.newBuilder()
    .expireAfterWrite(5, TimeUnit.MINUTES).maximumSize(10_000).build();

NodeHook.WrapCall<WmsState> scheduleCacheHook = (nodeId, state, config, action) -> {
    if (!"ai_schedule".equals(nodeId)) return action.apply(nodeId, state, config);
    String cacheKey = state.sku() + ":" + state.warehouseId();
    Map<String, Object> cached = scheduleCache.getIfPresent(cacheKey);
    if (cached != null) {
        log.info("[WMS][CACHE HIT] {}", cacheKey);
        return CompletableFuture.completedFuture(cached);
    }
    return action.apply(nodeId, state, config).thenApply(r -> {
        scheduleCache.put(cacheKey, r);
        return r;
    });
};

// ============ 7. 注册所有钩子到 StateGraph ============
var graph = new StateGraph(WmsState::new)
    .addNode("validate_order", validateOrderNode)
    .addNode("ai_schedule", aiScheduleNode)
    .addNode("manual_override", manualOverrideNode)
    .addNode("call_carrier_api", callCarrierApiNode)

    // 全局钩子(对所有节点生效)
    .addBeforeCallNodeHook(wmsLogHook)
    .addAfterCallNodeHook(metricsHook)
    .addAfterCallNodeHook(piiMaskHook)

    // ID 特定钩子(只对特定节点生效)
    .addBeforeCallNodeHook("manual_override", adminOnlyHook)
    .addWrapCallNodeHook("call_carrier_api", carrierApiRetryHook)
    .addWrapCallNodeHook("ai_schedule", scheduleCacheHook)

    .addEdge(START, "validate_order")
    .addEdge("validate_order", "ai_schedule")
    .addEdge("ai_schedule", "call_carrier_api")
    .addEdge("call_carrier_api", END)
    .addEdge("manual_override", END)
    .compile();

这一段代码覆盖了 6 个业务场景的横切关注点,业务节点本身(validateOrderNode / aiScheduleNode)只关注核心逻辑,日志 / 鉴权 / 埋点 / 限流 / 脱敏 / 缓存全部通过钩子外挂 —— 加新节点时,横切逻辑自动生效。

7. 决策树(用 Before/After 还是 Wrap?)

8. 5 个避坑

❶ BeforeCall / AfterCall LIFO,WrapCall FIFO —— 顺序错了行为完全不同

注册 hookA 再注册 hookB,BeforeCall 执行顺序是 B → A(后注册先跑,像栈);WrapCall 是 A → B(像洋葱层)。混用日志钩子和监控钩子时,先在纸上画洋葱图,否则日志时间戳和监控耗时对不上。

❷ hook 抛异常会中断整个 graph 执行,不会继续下一个节点

在 BeforeCall 里抛 SecurityException 鉴权失败,整个 graph 直接失败,不会"跳过这个节点去下一个"。要想跳过/路由分支,必须用 WrapCall 返回不同 result,而不是抛异常。

❸ WrapCall 里忘了调 action.apply(...),节点永远不执行

WrapCall 拿到的是 action 引用,不显式调用 action.apply 就不执行原节点(缓存命中短路除外)。常见 bug:复制 WrapCall 模板忘了改 return 语句,所有节点返回空 Map。

❹ 全局钩子对所有节点生效,包括 START 和 END 的"伪节点"

注册全局 BeforeCall 后,每次图执行都会触发 START 和 END 两个特殊节点的 hook(它们的 nodeId 是 "__START__" / "__END__")。在 hook 里加 if 判断:if ("__START__".equals(nodeId)) return Map.of();

❺ EdgeHook 只对条件边生效,对静态 addEdge(src, dst) 不触发

静态边没有 hook 时机(因为没有"计算过程")。要给静态边加审计,得改成条件边(lambda 始终返回 dst,但有 hook 时机)。

9. 速查表

API签名用途
addBeforeCallNodeHook(hook)全局注册所有节点执行前
addBeforeCallNodeHook(nodeId, hook)ID 特定指定节点执行前
addAfterCallNodeHook(hook)全局所有节点执行后
addAfterCallNodeHook(nodeId, hook)ID 特定指定节点执行后
addWrapCallNodeHook(hook)全局包裹所有节点
addWrapCallNodeHook(nodeId, hook)ID 特定包裹指定节点
addBeforeCallEdgeHook(...)同 Node条件边前
addAfterCallEdgeHook(...)同 Node条件边后
addWrapCallEdgeHook(...)同 Node包裹条件边

10. 本章小结

钩子 = 横切关注点外挂层。NodeHook × EdgeHook × 3 时机 × 全局 / ID 特定,组合出"业务纯净 + 运维全能"的图系统。
