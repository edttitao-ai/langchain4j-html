05AI Services(高级门面 API)

ch01-04 你写的是底层调用(Builder + chat)。AI Services 是 LangChain4j 推荐的高级门面——你只写 interface,LangChain4j 给你动态代理实现。类比 Spring Data JPA / Retrofit。

一句话定性:AiServices.create(Interface.class, chatModel) 返回 interface 的代理对象。方法签名 = API,注解 = 配置。LangChain4j 自动处理 prompt 拼装 + memory + tools + 流式。

1. 业务场景

老板:"我们 AI 客服项目有 20 个功能(分类/抽取/闲聊/翻译/总结...),每个功能都要写一遍 Builder + chat,代码重复得想哭。"

解法:每个功能只写 interface 一个方法,LangChain4j 用 JDK 动态代理自动实现。

5 个 AI Services 能解决的事

  • 统一入口 — 一个 Assistant 接口代替一堆 Builder
  • System 提示词模板 — @SystemMessage("你是 Java 专家")
  • 多用户记忆隔离 — @MemoryId + ChatMemoryProvider
  • 工具调用 — .tools(new MyTools())
  • RAG — .contentRetriever(...)(把检索当工具)

2. 核心概念:动态代理

跟 Spring Data JPA、Retrofit 同思路:

// 1. 你只写 interface(声明式)
interface Assistant {
    String chat(String userMessage);
}

// 2. LangChain4j 反射 + JDK Proxy 实现它
ChatModel model = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o-mini")
        .build();

Assistant assistant = AiServices.create(Assistant.class, model);

// 3. 跟普通方法一样调用,LangChain4j 在背后拼 prompt + 调 chat + 处理结果
String answer = assistant.chat("Hello");   // → "Hello, how can I help you?"

3. 6 个最常用注解

注解位置作用
@SystemMessage方法系统提示词,可写死 / 模板 / 读资源文件
@UserMessage方法 / 参数用户消息模板,支持 {{it}} / {{变量}}
@V("name")参数自定义模板变量名({{name}} 引用)
@MemoryId参数多用户/多会话记忆的 key
@Tool方法把方法暴露给 LLM 调用(下章详讲)
@ToolMemoryId方法参数工具调用时也能拿到 memoryId

4. 注解实战(@SystemMessage + @UserMessage)

用"朋友"角色扮演做示例:

interface Friend {
    @SystemMessage("You are a good friend of mine. Answer using slang.")
    String chat(String userMessage);
}

Friend friend = AiServices.create(Friend.class, model);
String answer = friend.chat("Hello");  // → "Hey! What's up?"

用 {{it}} 模板,把参数嵌入 UserMessage:

interface Friend {
    @UserMessage("You are a good friend. Answer using slang. {{it}}")
    String chat(String userMessage);
}

// 改用 @V 自定义变量名
interface Friend {
    @UserMessage("你是我的好朋友,回答用俚语。{{message}}")
    String chat(@V("message") String userMessage);
}

💡 提示:@SystemMessage(fromResource = "my-prompt.txt") 可以从 classpath 读 prompt 模板文件,生产推荐——改 prompt 不用重编译。

5. 多用户记忆隔离(@MemoryId + ChatMemoryProvider)

电商客服多用户同时聊,每个用户独立 memory,关键就 2 行:

interface Assistant {
    String chat(@MemoryId int memoryId, @UserMessage String message);
}

Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .chatMemoryProvider(memoryId -> MessageWindowChatMemory.withMaxMessages(10))
        .build();

// 用户 1 说话,只影响 memoryId=1 的会话
String a1 = assistant.chat(1, "你好,我叫 Klaus");
// 用户 2 说话,只影响 memoryId=2 的会话,互不串扰
String a2 = assistant.chat(2, "你好,我叫 Francine");

⚠️ 警告:官方明示 —— 同一 @MemoryId 的 AI Service 不能并发调用,会导致 ChatMemory 损坏(列表被两个线程同时改)。生产用线程池隔离,或者外部加锁。

6. 接入工具 / RAG / 审核

AI Services 几乎所有 ch01-04 的能力都能用一行 builder 接入:

Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .chatMemoryProvider(memoryId -> MessageWindowChatMemory.withMaxMessages(10))
        .tools(new MyTools())                                // 工具调用(ch06 详讲)
        .contentRetriever(EmbeddingStoreContentRetriever...)    // RAG 检索(高级篇)
        .moderationModel(moderationModel)                          // 内容审核(自动拦截违规)
        .build();

7. AI Services 返回类型

方法返回类型决定行为:

  • String — 纯文本回答
  • boolean / int / enum — 分类 / 抽取(自动 JSON 解析)
  • POJO — 复杂结构(自动 JSON → 对象映射)
  • List<POJO> — 列表
  • Result<T> — 包一层,带 token 用量 / finishReason 等元数据
  • TokenStream — 流式输出(接 ch04)
  • Flux<String> — Reactor 响应式流(需 langchain4j-reactor 模块)

8. 实战:Miles of Smiles 多 AI 服务拆分

官方推荐的"小而专"思路 —— 把复杂业务拆成 2+ 个 AI Service 各自测试:

// 子服务 1:只判断用户是否打招呼(走 LLM)
interface GreetingExpert {
    @UserMessage("Is the following text a greeting? Text: {{it}}")
    boolean isGreeting(String text);
}

// 子服务 2:正式聊天(带 RAG 知识库)
interface ChatBot {
    @SystemMessage("You are a polite chatbot of a company called Miles of Smiles.")
    String reply(String userMessage);
}

// 业务代码:如果用户只是打招呼,直接走死字符串回复,根本不打 LLM
String handle(String userInput) {
    if (greetingExpert.isGreeting(userInput)) {
        return "你好!有什么可以帮您?";  // 零 LLM 成本
    }
    return chatBot.reply(userInput);     // 真要走 LLM + RAG
}

💡 价值:(1) 子服务可独立测试 / 独立评估 (2) 子服务可独立调参数(打招呼 = 0.0 temperature,正式聊天 = 0.5) (3) 简单分支不走 LLM,省 token + 减延迟。

9. 避坑指南

坑 1 · AiServices.create() 不能接 StreamingModel

AiServices.create(Interface.class, streamingModel) 会抛异常。要流式必须用 builder 模式:AiServices.builder().streamingChatModel(...).build()。

坑 2 · @MemoryId 同 ID 并发 = 数据损坏

同一 memoryId=1 两个请求同时打进来,两个线程同时改 List<ChatMessage> = ConcurrentModificationException。要加锁 / 串行队列 / 线程隔离。

坑 3 · interface 方法名要语义化

方法名会进 finishReason 和日志:chat() / isPositive() / generateOutline()。别用 a() / b() / doIt() 这种没意义的名字,debug 时找不到问题。

坑 4 · 模板里忘写 {{it}} = 空白 prompt

@UserMessage("Tell me a joke") 不带 {{it}},参数 userMessage 会被忽略。每次返回同一个笑话。检查:每个 @UserMessage 都要 {{变量}} 引用参数。

坑 5 · 接口继承 ChatMemoryAccess 才能 evict

用 @MemoryId 时,memory 越来越多会内存泄漏。要 evict 必须让 interface 继承 ChatMemoryAccess,然后调 assistant.getChatMemory(id).clear()。
