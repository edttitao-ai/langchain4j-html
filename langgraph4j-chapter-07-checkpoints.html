07 检查点(存档 / 读档 / 时间旅行)

PostgresSaver × Checkpoint × getStateHistory × lastStateOf × release · 6 业务场景

一句话定性:检查点 = graph 状态的持久化存档。LangGraph4j 提供 PostgresSaver(基于 PostgreSQL)把每个节点执行后的 state 存到 DB;崩了能从最近存档恢复;支持 getStateHistory() 看历史 + lastStateOf() 拿最近一次 + release() 释放线程。内存缓存层减少 DB 往返。

核心价值:长跑 agent 的"游戏存档"机制 —— 进程重启 / 节点失败 / 人想介入修改 state 时都能"读档继续",而不是从头跑浪费 token + 浪费时间。

1. 业务场景

老板:"用户跟 AI 客服聊到第 5 轮时,服务器 OOM 重启了 —— 用户回来要从头聊,前 4 轮的订单查询 / 物流跟踪结果全没了,用户体验崩。"

解法:用 检查点 —— graph 每执行完一个节点就把 state 序列化存到 PostgreSQL,进程重启后从最近存档恢复,用户接着第 5 轮聊,不用从头来。

6 个检查点能解决的事

  • 💾 进程崩溃恢复 — OOM / 部署 / 服务器挂了,重启后从 PostgresSaver 读最近存档继续跑,token 不浪费
  • 👤 人介入修改 state — agent 跑飞了调错工具,人工看一眼 getStateHistory(),改 state 后"读档重跑"
  • ⏪ 时间旅行 debug — 复杂 agent 出问题,看历史每一步 state,定位"哪一步把 state 搞坏了"
  • 🔄 长任务断点续跑 — 跑批处理跑一半到下班了,关机明天启动从最近存档继续,不用从 step 1 重跑
  • 📊 审计 / 合规 — 金融 / 医疗场景需要每一步决策可追溯,checkpoint history 就是天然审计日志
  • 🧪 测试可重现 — 同一 thread_id + 同一输入 = 同一 state history,测试用例可重现

💡 什么时候不需要:单次简单调用(没状态可存档)/ 内存版 MemorySaver 已经够用(不需要 Postgres)/ 对延迟极敏感(每次 save 多 1-5ms DB 往返)/ state 含敏感数据需加密落盘(额外加密层)。

2. 核心概念

2.1 检查点三件套

要素API作用
存档CompileConfig.checkpointSaver(saver)编译时挂上 saver,每个节点自动存档
查历史workflow.getStateHistory(runnableConfig)返回 List<Checkpoint>,按时间倒序
取最近workflow.lastStateOf(runnableConfig)返回 Optional<NodeOutput>,最近一次存档
释放saver.release(runnableConfig)释放该 thread 占用的资源(releaseThread=false 时必须调)

2.2 Saver 构建器

PostgresSaver saver = PostgresSaver.builder()
    .host("localhost")        // ← DB 地址
    .port(5432)                // ← DB 端口
    .user("admin")             // ← 用户名
    .password("your_password") // ← 密码
    .database("lg4j-store")    // ← 数据库名
    .stateSerializer(serializer) // ← state 序列化器(ObjectStreamStateSerializer / JacksonSerializer)
    .dropTablesFirst(false)    // ← true:启动时先 drop 表(开发用)
    .createTables(true)        // ← true:启动时自动建表(生产建议手动迁移)
    .build();

2.3 编译配置关键开关

配置默认值作用
checkpointSaver(saver)null(无存档)挂上后每个节点执行后自动 save
releaseThread(true)truetrue:节点执行完立即释放线程;false:保留线程供 release() 显式释放

⚠️ releaseThread 配对使用:releaseThread(false) 时,必须显式调 saver.release(runnableConfig) 释放资源,否则线程 / 连接泄漏。常用于"需要异步存档 + 后续手动控制"的场景。

3. 极简调用(4 行存档 + 读档)

最小可运行 demo:编译时挂 saver → invoke → 看历史 → 重启后读档:

// 1. 初始化 saver
var saver = PostgresSaver.builder()
    .host("localhost").port(5432).user("admin").password("xxx").database("lg4j-store")
    .stateSerializer(new ObjectStreamStateSerializer<>(AgentState::new))
    .createTables(true)
    .build();

// 2. 编译时挂存档
var compileConfig = CompileConfig.builder().checkpointSaver(saver).build();
var workflow = graph.compile(compileConfig);

// 3. 跑一次,自动存档
var runnableConfig = RunnableConfig.builder().build();
workflow.invoke(Map.of("input", "test1"), runnableConfig);  // ← 跑完所有节点,每步存档

// 4. 看历史
List<Checkpoint> history = workflow.getStateHistory(runnableConfig);
assertEquals(2, history.size());   // START + agent_1 + END 共 2-3 个 checkpoint

Optional<NodeOutput> last = workflow.lastStateOf(runnableConfig);
last.ifPresent(s -> {
    assertEquals("agent_1", s.node());
    assertEquals(END, s.next());
});

4. 检查点完整实战

4.1 进程崩溃恢复(核心场景)

// 场景:agent 跑多步,中间崩了,重启后从最近存档继续
var stateSerializer = new ObjectStreamStateSerializer<>(AgentState::new);

// ====== 第一次启动:跑一半崩了 ======
var saver1 = PostgresSaver.builder()
    .host("localhost").port(5432).user("admin").password("xxx").database("lg4j-store")
    .stateSerializer(stateSerializer)
    .createTables(true)
    .build();

var compileConfig1 = CompileConfig.builder()
    .checkpointSaver(saver1)
    .releaseThread(false)   // ← 保留线程,后续手动 release
    .build();
var runnableConfig = RunnableConfig.builder().build();
var workflow1 = graph.compile(compileConfig1);

try {
    workflow1.invoke(Map.of("input", "test1"), runnableConfig);
} catch (Exception e) {
    log.error("中途崩了", e);
    // 注意:不调 release(),存档已经在 DB 里了
}

// ====== 服务器重启后:新建 saver,重新 compile,读档继续 ======
var saver2 = PostgresSaver.builder()
    .host("localhost").port(5432).user("admin").password("xxx").database("lg4j-store")
    .stateSerializer(stateSerializer)
    .build();   // ← createTables=false,因为表已存在

var compileConfig2 = CompileConfig.builder()
    .checkpointSaver(saver2)
    .releaseThread(false)
    .build();
var workflow2 = graph.compile(compileConfig2);

// 读最近存档 + 历史
var history = workflow2.getStateHistory(runnableConfig);
var lastSnapshot = workflow2.lastStateOf(runnableConfig);
log.info("崩前最后状态: node={}, next={}", lastSnapshot.get().node(), lastSnapshot.get().next());

// 重新 invoke 会从最近存档继续(不是从头跑)
var result = workflow2.invoke(Map.of("input", "test1"), runnableConfig);
saver2.release(runnableConfig);   // ← 显式释放

log.info("共 {} 个 checkpoint,按时间倒序:", history.size());

4.3 人介入修改 state + 重跑

// 场景:agent 调错工具把 state 搞坏了,人工改 state 后重跑
var history = workflow.getStateHistory(runnableConfig);
var brokenCheckpoint = history.get(1);  // 选第 1 步的状态

// 改 state(比如强制重置某个字段)
var patchedState = new HashMap<>(brokenCheckpoint.state().data());
patchedState.put("retry_count", 0);   // ← 重置重试计数
patchedState.put("manual_override", true);

// 用修改后的 state 重新 invoke
var patchedInput = new HashMap<String, Object>(patchedState);
patchedInput.put("input", "test1");

var newRunnableConfig = RunnableConfig.builder().build();
workflow.invoke(patchedInput, newRunnableConfig);  // ← 从修改后的 state 继续跑

5. 实战:跨境电商 AI 客服 + 存档恢复(6 业务场景落地)

跨境电商 AI 客服,用户对话经常跨多次会话(用户问一半走了 / 手机没电了 / 隔天再来)。存档/读档是核心刚需 —— 让用户从上次中断的地方继续,不用重复输入订单号 / 物流单号。

业务场景映射

业务场景存档策略实现要点
💾 OOM 重启恢复每节点存档PostgresSaver + releaseThread(false) + 启动时读最近存档
👤 用户跨天继续对话thread_id 关联存档runnableConfig.threadId("user-123-session-1") + lastStateOf 读
⏪ 客服介入排错getStateHistory 时间旅行客服后台看每步 state,人工改后重 invoke
🔄 长批处理断点续跑夜间跑一半关机启动时遍历所有 thread_id,从最近存档继续
📊 决策审计(合规)getStateHistory 全留痕每步 state 永久存档,合规审查可拉历史
🧪 测试可重现同一 thread_id 复现测试用例固定 thread_id + 输入,断言 history 内容

完整代码

// ============ 1. 全局 Saver 单例(连接池) ============
public class CheckpointService {
    private final PostgresSaver saver;

    public CheckpointService(DataSource ds) {
        this.saver = PostgresSaver.builder()
            .host(ds.getHost()).port(ds.getPort())
            .user(ds.getUser()).password(ds.getPassword())
            .database(ds.getDatabase())
            .stateSerializer(new ObjectStreamStateSerializer<>(AgentState::new))
            .build();
    }

    public PostgresSaver saver() { return saver; }
}

// ============ 2. 用户跨天继续对话(核心场景) ============
public class CustomerAgentService {

    private final CompiledGraph<AgentState> workflow;
    private final CheckpointService checkpointService;

    public CustomerAgentService(CompiledGraph<AgentState> workflow, CheckpointService cs) {
        this.workflow = workflow;
        this.checkpointService = cs;
    }

    // 用户发起对话:用 threadId 关联,跨天也能找到
    public String chat(String userId, String sessionId, String userInput) {
        String threadId = userId + ":" + sessionId;   // ← 唯一 thread_id
        var config = RunnableConfig.builder().threadId(threadId).build();

        // 读最近存档(用户上次聊到哪了)
        var lastState = workflow.lastStateOf(config);
        Map<String, Object> input = new HashMap<>();
        if (lastState.isPresent()) {
            log.info("[AGENT] 用户 {} 上次聊到: {}", userId, lastState.get().node());
            input.putAll(lastState.get().state().data());   // ← 继承上次 state
            input.put("input", userInput);                  // ← 加新输入
        } else {
            input.put("input", userInput);
            input.put("user_id", userId);
        }

        // 跑(自动存档每步)
        var compileConfig = CompileConfig.builder()
            .checkpointSaver(checkpointService.saver())
            .releaseThread(false)
            .build();
        var result = workflow.invoke(input, config);
        checkpointService.saver().release(config);   // ← 显式释放
        return result.get("agent_response").orElse("").toString();
    }

    // ============ 3. 客服后台查看用户对话历史(时间旅行) ============
    public List<Checkpoint> getUserChatHistory(String userId, String sessionId) {
        String threadId = userId + ":" + sessionId;
        var config = RunnableConfig.builder().threadId(threadId).build();
        return workflow.getStateHistory(config);
    }

    // ============ 4. 客服介入修改 state 后重跑 ============
    public String interveneAndRerun(String userId, String sessionId, int checkpointIdx,
                                     Map<String, Object> stateOverrides) {
        String threadId = userId + ":" + sessionId;
        var config = RunnableConfig.builder().threadId(threadId).build();
        var history = workflow.getStateHistory(config);

        if (checkpointIdx < 0 || checkpointIdx >= history.size()) {
            throw new IllegalArgumentException("Invalid checkpoint idx: " + checkpointIdx);
        }

        var cp = history.get(checkpointIdx);
        var newInput = new HashMap<String, Object>(cp.state().data());
        newInput.putAll(stateOverrides);   // ← 应用客服的修改

        var compileConfig = CompileConfig.builder()
            .checkpointSaver(checkpointService.saver())
            .releaseThread(false)
            .build();
        var result = workflow.invoke(newInput, config);
        checkpointService.saver().release(config);
        return result.get("agent_response").orElse("").toString();
    }

    // ============ 5. 夜间批处理断点续跑 ============
    public void resumeAllIncompleteJobs() {
        // 假设有 job 表记录所有 thread_id
        List<String> allThreads = jobRepo.findAllThreadIds();
        for (String threadId : allThreads) {
            var config = RunnableConfig.builder().threadId(threadId).build();
            var last = workflow.lastStateOf(config);
            if (last.isPresent() && !END.equals(last.get().next())) {
                log.info("[BATCH] 续跑 thread: {}, 上次停在: {}", threadId, last.get().node());
                // 从最近存档继续
                var result = workflow.invoke(last.get().state().data(), config);
                checkpointService.saver().release(config);
                jobRepo.markCompleted(threadId);
            }
        }
    }

    // ============ 6. 审计日志(合规) ============
    public List<Map<String, Object>> getAuditTrail(String userId, String sessionId) {
        return getUserChatHistory(userId, sessionId).stream()
            .map(cp -> {
                Map<String, Object> entry = new HashMap<>();
                entry.put("node", cp.node());
                entry.put("next", cp.next());
                entry.put("state", cp.state().data());
                entry.put("timestamp", cp.timestamp());
                return entry;
            })
            .collect(Collectors.toList());
    }
}

6. 决策树(用哪种存档策略?)

7. 5 个避坑

❶ releaseThread(false) 必须显式 release(),否则线程 / 连接泄漏

设了 releaseThread(false) 后,每次 invoke 完必须调 saver.release(runnableConfig)。常见 bug:复制示例代码忘了加 release,跑 1000 次后线程池打满 + DB 连接耗尽。建议包成 try-with-resources 风格。

❷ stateSerializer 必须全局一致,换了就读不出老存档

PostgresSaver 用 ObjectStreamStateSerializer 存的 state,换 JacksonSerializer 读出来直接报 ClassNotFoundException / InvalidClassException。序列化器一旦定下来就不能换,否则历史存档作废。建议从一开始就用一个稳定的序列化器。

❸ createTables(true) 只在首次启动用,生产用 Flyway / Liquibase 迁移

createTables(true) 自动建表 = 方便开发但生产危险 —— 不会跟踪 schema 版本,字段变更 / 索引优化 / 数据迁移全失控。生产用 Flyway / Liquibase 管理 schema 变更,createTables(false) 让程序假设表已存在。

❹ getStateHistory() 返回的列表是"视图"不是快照,不要边遍历边 invoke

getStateHistory() 返回的 List<Checkpoint> 是从 saver 内存缓存读的实时视图,如果你在遍历 history 的同时又在另一个线程 invoke 同 thread 的 workflow,可能抛 ConcurrentModificationException。建议遍历前先 new ArrayList<>(history) 拷贝一份。

❺ PostgresSaver 的内存缓存不会自动失效,跨进程读会"看不到"对方写的

saver 内部有内存缓存(减少 DB 往返),但缓存是进程级的。A 进程写了存档,B 进程新建 saver 实例后内存缓存是空的,B 读的是 DB(正确)。但如果 B 进程复用了一个 saver 实例,缓存可能"过期"。重启进程 / 新建 saver 实例是安全做法。
