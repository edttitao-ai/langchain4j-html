06 取消(超时 / 用户取消 / 子图传播)

AsyncGenerator.cancel() × mayInterruptIfRunning × forEachAsync / for-each 两种消费 × 子图传播 · 6 业务场景

一句话定性:取消 = 主动终止正在执行的 graph 流。LangGraph4j 基于 java-async-generator 库的取消机制,workflow.stream(...) 返回的 AsyncGenerator 实例可以调用 cancel(mayInterruptIfRunning)。true = 立即中断线程抛 InterruptedException,false = 优雅停止(当前节点跑完再停);子图自动传播取消。

核心价值:长跑图(批处理 / 复杂 agent 循环 / 外部 API 等)在"用户不想等了 / 超时了 / 资源不够"时能主动停,而不是等图自然跑完浪费时间 + 浪费 token。

1. 业务场景

老板:"用户点了一个 AI 客服按钮,agent 在循环调工具 / 等外部 API。结果用户等不及点'取消',但 agent 还在后台跑 —— token 在烧、API 在调,等真正停了已经欠费 5 块钱了。"

解法:用 取消 —— graph 流式执行(stream())返回 AsyncGenerator,持有引用就能随时 cancel()。子图自动传播,父图取消子图也跟着停,不会"父停了子还在烧"。

6 个取消能解决的事

  • 🛑 用户点"停止"按钮 — 前端发个请求,后端立刻调 cancel(true) 中断,token 不再烧
  • ⏱️ 5 秒超时兜底 — 异步任务 CompletableFuture.get(5, SECONDS),超时调 cancel(false) 让当前节点跑完
  • 💸 成本熔断 — 本次会话 token 用超预算,立即 cancel(true),比"让它跑完欠 5 块"省
  • 🧪 调试中断 — 复杂 agent 跑飞了(死循环 / 调错工具),开发时手动 cancel,看已累积的 state 排错
  • 🧹 资源回收 — 节点持有的连接 / 文件句柄,配合 try-with-resources + cancel 实现优雅关闭
  • 🌲 子图级联停止 — 父 agent 取消,所有正在跑的子 agent 自动停(取消传播)

💡 什么时候不需要:同步 execute() 调用(没有流可取消)/ 图非常短(单节点秒完)/ 节点全是纯计算没有外部 IO(取消意义不大)/ 用线程池硬隔离 + 进程级 kill 的场景(更粗暴)。

2. 核心概念

2.1 取消机制三要素

要素API作用
触发取消generator.cancel(boolean mayInterruptIfRunning)true = 立即中断线程;false = 当前节点跑完再停
检查状态generator.isCancelled()返回 boolean,流是否已取消
异常传播CompletableFuture / for-each 终止异步场景抛 InterruptedException;同步场景 hasNext() 返回 false

2.2 两种消费方式 × 取消行为

2.3 取消传播(子图级联)

✓ 取消自动传播到子图。父图调 cancel(...),所有当前正在执行的子图同步收到取消信号,不会"父停了子还在烧"。这是 LangGraph4j 内置行为,不需要手动通知子图。

3. 极简调用(2 行取消图流)

最小可运行 demo,启动图流后 500ms 自动取消:

import org.bsc.async.AsyncGenerator;

AsyncGenerator<NodeOutput<?>> generator = workflow.stream(GraphInput.noArgs(), RunnableConfig.builder().build());

// 500ms 后在另一个线程取消
CompletableFuture.runAsync(() -> {
    try { Thread.sleep(500); } catch (InterruptedException e) { throw new RuntimeException(e); }
    generator.cancel(true);   // ← 一行立即取消
});

// 消费流(异步)
CompletableFuture<String> result = generator.forEachAsync(output -> 
    System.out.println("node: " + output.node()))
    .exceptionally(ex -> {
        assertTrue(generator.isCancelled());  // ← 检查取消状态
        return "CANCELLED";
    });

500ms 后图被中断,forEachAsync 的 CompletableFuture 抛 InterruptedException,exceptionally 兜底返回 "CANCELLED"。

4. 两种取消策略实战

4.1 cancel(true) 立即取消 + 异常处理

// 场景:用户点"停止"按钮,立刻中断,不等当前节点跑完
AsyncGenerator<NodeOutput<AgentState>> gen = workflow.stream(inputs, config);

CompletableFuture<String> future = gen.forEachAsync(output -> {
    log.info("正在执行: {}", output.node());
}).handle((result, ex) -> {
    if (ex != null) {
        if (ex.getCause() instanceof InterruptedException) {
            log.warn("用户中断,清理资源");
            cleanupResources(gen);  // 关闭文件句柄 / DB 连接
            return "INTERRUPTED";
        }
        return "ERROR: " + ex.getMessage();
    }
    return "COMPLETED";
});

// 用户点"停止" → WebSocket 发 cancel 信号
public void onUserCancel() {
    boolean cancelled = gen.cancel(true);
    log.info("cancel(true) 返回: {}", cancelled);
    // 中断执行线程,CompletableFuture 异常完成,future.handle() 兜底
}

4.2 cancel(false) 优雅取消 + 当前节点跑完

// 场景:5 秒超时兜底,让当前节点跑完再停,不浪费已开始的 IO
AsyncGenerator<NodeOutput<AgentState>> gen = workflow.stream(inputs, config);

CompletableFuture<NodeOutput<AgentState>> future = gen.forEachAsync(output -> {
    log.info("正在执行: {}", output.node());
});

// 5 秒超时
try {
    NodeOutput<AgentState> lastOutput = future.get(5, TimeUnit.SECONDS);
    log.info("5 秒内跑完,最后节点: {}", lastOutput.node());
} catch (TimeoutException e) {
    log.warn("5 秒超时,优雅停止");
    gen.cancel(false);   // ← 当前节点跑完再停
    // future 会正常完成(不抛异常),但 isCancelled() 返回 true
    Thread.sleep(200);  // 等一下,让 generator 走完关闭流程
    assertTrue(gen.isCancelled());
    log.info("已停止,不再烧 token");
}

4.3 for-each 同步消费 + 取消

// 场景:CLI 工具 / 批跑脚本 / 调试观察(同线程消费)
AsyncGenerator<NodeOutput<AgentState>> gen = workflow.stream(inputs, config);

// 另一线程 500ms 后取消
CompletableFuture.runAsync(() -> {
    try { Thread.sleep(500); } catch (InterruptedException e) { return; }
    gen.cancel(true);  // 或 false,行为一致
});

NodeOutput<AgentState> currentOutput = null;
try {
    for (var output : gen) {
        log.info("正在执行: {}", output.node());
        currentOutput = output;
    }
} catch (Exception e) {
    log.error("迭代异常", e);
}

// 取消后 hasNext() 返回 false,循环自然退出
assertNotNull(currentOutput);                    // 至少跑了一个节点
assertNotEquals(END, currentOutput.node());      // 没到 END 就停了
assertTrue(gen.isCancelled());                   // 取消状态确认

5. 实战:跨境电商 AI 客服 + 取消控制(6 业务场景落地)

跨境电商 AI 客服 agent,长跑场景非常多 —— 调物流 API / 调 ERP 查库存 / LLM 多步推理。用户随时可能取消,系统必须能立即停 + 不浪费 token + 资源优雅回收。

WMS 业务场景映射

业务场景取消策略实现要点
🛑 用户点"停止"按钮cancel(true) 立即中断WebSocket 推信号 → 后端 cancel(true)
⏱️ 30 秒超时兜底cancel(false) 优雅停future.get(30, SECONDS) → TimeoutException → cancel
💸 成本熔断(超 1 元 token)cancel(true) 立即停累计 token 花费超阈值 → cancel + 提示用户
🧹 资源回收cancel(false) + finallyDB 连接 / 临时文件 / 锁在 finally 里释放
🌲 子图级联停止父 cancel → 子自动停主 agent cancel,所有子 agent(查订单/查库存)同步停
🧪 调试死循环cancel(true) + 看 state开发态手动 cancel,看累积 state 排错

完整代码

// ============ 1. 启动流 + 注册取消控制器 ============
public class CancellableAgentRunner {

    private AsyncGenerator<NodeOutput<AgentState>> generator;
    private final AtomicBoolean userCancelled = new AtomicBoolean(false);
    private final AtomicReference<Double> tokenCost = new AtomicReference<<>(0.0);

    public CompletableFuture<String> run(CompiledGraph<AgentState> graph, Map<String, Object> inputs) {
        this.generator = graph.stream(inputs, RunnableConfig.builder().build());

        // 异步消费流
        return generator.forEachAsync(output -> {
            String nodeId = output.node();
            log.info("[AGENT] 正在执行节点: {}", nodeId);
            // 累计 token 成本(每次 LLM 调用后更新)
            if (nodeId.startsWith("llm_")) {
                tokenCost.updateAndGet(c -> c + estimateCost(output.state()));
            }
        }).handle((result, ex) -> {
            // 取消 / 异常 / 正常完成统一兜底
            if (ex != null) {
                if (ex.getCause() instanceof InterruptedException) {
                    log.warn("[AGENT] 被中断,token 已烧: ¥{}", tokenCost.get());
                    return "INTERRUPTED";
                }
                log.error("[AGENT] 执行异常", ex);
                return "ERROR: " + ex.getMessage();
            }
            return "COMPLETED";
        });
    }

    // ============ 2. 用户取消按钮(WebSocket 推信号) ============
    public boolean onUserCancel() {
        userCancelled.set(true);
        boolean cancelled = generator.cancel(true);   // ← 立即中断
        log.info("[AGENT] 用户取消,结果: {}, token 已烧: ¥{}", cancelled, tokenCost.get());
        return cancelled;
    }

    // ============ 3. 30 秒超时兜底(优雅停) ============
    public String runWithTimeout(CompiledGraph<AgentState> graph, Map<String, Object> inputs, long timeoutSec) {
        try {
            return run(graph, inputs).get(timeoutSec, TimeUnit.SECONDS);
        } catch (TimeoutException e) {
            log.warn("[AGENT] {} 秒超时,优雅停止", timeoutSec);
            generator.cancel(false);   // ← 当前节点跑完再停
            // 等 generator 走完关闭流程
            try { Thread.sleep(500); } catch (InterruptedException ie) { Thread.currentThread().interrupt(); }
            return "TIMEOUT_GRACEFUL";
        } catch (Exception e) {
            log.error("[AGENT] 执行异常", e);
            return "ERROR";
        }
    }

    // ============ 4. 成本熔断(超 1 元立即停) ============
    public void startCostWatchdog(double maxCostYuan) {
        // 后台线程每 100ms 检查 token 成本
        CompletableFuture.runAsync(() -> {
            while (!Thread.currentThread().isInterrupted() && !generator.isCancelled()) {
                if (tokenCost.get() > maxCostYuan) {
                    log.warn("[AGENT] token 成本 ¥{} 超阈值 ¥{},立即停止", tokenCost.get(), maxCostYuan);
                    generator.cancel(true);   // ← 立即停
                    break;
                }
                try { Thread.sleep(100); } catch (InterruptedException e) { break; }
            }
        });
    }

    // ============ 5. 资源回收(配合 cancel 用 try-with-resources) ============
    public String runWithResourceCleanup(CompiledGraph<AgentState> graph, Map<String, Object> inputs) {
        AsyncGenerator<NodeOutput<AgentState>> gen = graph.stream(inputs, RunnableConfig.builder().build());
        List<AutoCloseable> resources = new ArrayList<>();
        try {
            return gen.forEachAsync(output -> {
                // 节点内可能打开 DB 连接 / 临时文件,登记到 resources
                if (output.node().equals("query_db")) {
                    resources.add(openDbConnection());
                }
            }).handle((r, ex) -> {
                if (ex != null && ex.getCause() instanceof InterruptedException) {
                    log.info("[AGENT] 被中断,清理 {} 个资源", resources.size());
                }
                return ex == null ? "COMPLETED" : "INTERRUPTED";
            }).get(30, TimeUnit.SECONDS);
        } catch (Exception e) {
            return "ERROR";
        } finally {
            // 不管成功 / 取消 / 异常,都关闭资源
            for (AutoCloseable r : resources) {
                try { r.close(); } catch (Exception ignored) {}
            }
            if (!gen.isCancelled()) gen.cancel(false);  // 确保流关闭
        }
    }

    private AutoCloseable openDbConnection() { return () -> log.info("DB 连接关闭"); }
    private double estimateCost(AgentState state) { return 0.05; }  // 简化估算
}

这一段覆盖了 6 个业务场景的取消控制 —— 用户主动取消、超时兜底、成本熔断、资源回收、子图传播、调试中断,所有取消场景都通过 generator.cancel(...) + isCancelled() + handle() 三件套统一收口。

6. 决策树(用 cancel(true) 还是 false?)

7. 5 个避坑

❶ 同步 execute() 没有流可取消,只有 stream() 才能 cancel

graph.execute(...) 是同步阻塞调用,执行完才返回,中途无法取消。必须用 graph.stream(...) 拿到 AsyncGenerator 实例才能 cancel。常见 bug:线上代码用 execute() 然后还想"中途取消",无解。

❷ 异步 cancel(true) 后,主线程别忘了等 generator 走完关闭流程

cancel(true) 中断执行线程后,AsyncGenerator 内部的清理逻辑(关闭子流、释放 buffer)仍在异步进行。主线程立即用 generator 可能拿到半状态。建议 Thread.sleep(200) 或监听 isCancelled() 确认清理完。

❸ forEachAsync 必须配 .handle() 或 .exceptionally() 接异常

cancel(true) 会让 CompletableFuture 异常完成,如果不接异常,异常被吞掉,调用方以为正常完成。正确写法:.handle((r, ex) -> ex != null ? "INTERRUPTED" : "OK")。

❹ 子图取消传播是单向的(父→子),子不能反向取消父

父图 cancel 会传播到所有子图;但子图 cancel 不会反向取消父图(父图可能还有别的子图在跑)。设计系统时,父子取消策略要单独设计,别假设"子停了父也停"。

❺ cancel 后 state 已经写入的部分不会回滚

cancel 中断执行,但已经执行的节点写入的 state 不会回滚(如已写入数据库的订单状态)。要做"事务性取消",得在 hook(见 lg05)里包 @Transactional + rollback,或在节点里检查 generator.isCancelled() 主动跳过副作用。

8. 速查表

API行为典型场景
generator.cancel(true)立即中断线程,抛 InterruptedException用户点"停止" / 成本熔断
generator.cancel(false)当前节点跑完再停,不抛异常超时兜底 / 资源回收
generator.isCancelled()检查是否已取消finally / 节点内判断
forEachAsync(...)异步线程消费,异常通过 CompletableFuture 传播Web 请求 / 异步任务
for (var o : gen)当前线程消费,hasNext() 返回 false 退出CLI / 批跑 / 调试
子图取消传播父 cancel → 子自动 cancel(单向)多 agent 嵌套

9. 本章小结

取消 = 流式图的"主动终止"机制。stream() 拿 AsyncGenerator,cancel(true/false) 触发停止,子图自动传播。
