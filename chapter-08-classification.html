08Classification(文本分类)

把一段文字归到预定义标签里:情感(正/负/中)、意图(查订单/退订/投诉)、实体(人名/地名/公司)。LangChain4j 提供2 种实现路径:LLM 直接判 vs 向量相似度。

一句话定性:AI Service 模式返回 enum 或 boolean = 极简分类。零成本上手,适合 90% 业务。要快 + 不烧 token 选 EmbeddingModelTextClassifier。

1. 业务场景

老板:"每天 10000 条用户评论,人工分类要 3 个客服。我们要做自动情感分类:正面/中性/负面,负面自动转人工处理。"

这就是典型的文本分类任务。LLM 时代前用 BERT 微调,现在直接让 LLM 判。

3 个真实场景

  • 客户评论情感分析 — 正面 / 中性 / 负面 → 负面自动告警
  • 用户意图识别 — 查订单 / 退订 / 投诉 → 路由到不同 AI 服务
  • 垃圾评论过滤 — 广告 / 正常 / 违规 → 违规直接屏蔽

2. 2 种实现方法

方法原理速度成本准确度
AI Service 判别LLM 直接读文字判断1-3 秒每次调 LLM高(可理解上下文)
EmbeddingModelTextClassifier向量化 + 余弦相似度匹配毫秒级本地推理中(依赖样例质量)

3. 方法 ①:AI Service 情感分类(主流)

用 ch05 的 AI Service 模式,直接返回 enum:

enum Sentiment { POSITIVE, NEUTRAL, NEGATIVE }

interface SentimentClassifier {
    @UserMessage("判断下面评论的情感倾向(只能从 POSITIVE/NEUTRAL/NEGATIVE 选一个):\n\n{{it}}")
    Sentiment classify(String text);
}

// 创建 + 调用
SentimentClassifier classifier = AiServices.create(SentimentClassifier.class, chatModel);
Sentiment s = classifier.classify("这家店服务太棒了!下次还来。");
System.out.println(s);   // → POSITIVE

返回 boolean = 极简二分类:

interface SpamDetector {
    @UserMessage("Is the following text spam? Text: {{it}}")
    boolean isSpam(String text);
}

SpamDetector detector = AiServices.create(SpamDetector.class, chatModel);
boolean spam = detector.isSpam("加我微信 xxx 优惠...");   // → true

4. Few-shot 提升准确度

LLM 分类"模糊地带"会猜错。给它几个示例(Few-shot)准确度立刻提升:

interface SentimentClassifier {
    @UserMessage("""
        判断下面评论的情感倾向,只能从 POSITIVE / NEUTRAL / NEGATIVE 选一个。

        示例:
        评论: "太好用了!推荐给朋友" → POSITIVE
        评论: "一般般,没什么特别" → NEUTRAL
        评论: "差评,再也不会买了" → NEGATIVE

        现在判断:
        评论: {{it}}
        """)
    Sentiment classify(String text);
}

5. 方法 ②:EmbeddingModelTextClassifier(本地快)

用向量相似度匹配 —— 不调 LLM,纯本地推理:

import dev.langchain4j.classification.EmbeddingModelTextClassifier;
import dev.langchain4j.model.embedding.onnx.allminilml6v2q.AllMiniLmL6V2QuantizedEmbeddingModel;

EmbeddingModel embeddingModel = new AllMiniLmL6V2QuantizedEmbeddingModel();

TextClassifier<String> classifier = EmbeddingModelTextClassifier.builder()
        .embeddingModel(embeddingModel)
        .examples(Map.of(
            "POSITIVE", List.of("太棒了", "非常满意", "推荐", "完美"),
            "NEGATIVE", List.of("垃圾", "差评", "再也不买", "浪费时间"),
            "NEUTRAL",  List.of("一般", "还行", "凑合", "可以接受")
        ))
        .build();

String result = classifier.classify("这家店服务太棒了!");
System.out.println(result);   // → POSITIVE

💡 优势:不调 LLM → 零 token 费用+ 毫秒级响应。10000 条评论批量分类 = 几秒搞定。适合离线批处理 / 高频低价值场景。

6. 2 种方法选型决策

7. 避坑指南

坑 1 · enum 标签名一定要全大写

返回 Sentiment 时 LLM 要把字符串解析成 enum。如果你的 enum 是 Positive / Negative(驼峰),LangChain4j 解析时可能大小写不匹配。建议 用 POSITIVE / NEUTRAL / NEGATIVE 全大写,与 Java enum 常量命名一致。

坑 2 · LLM 分类有"幻觉率"

LLM 不会 100% 准确。"一般般" 是 NEUTRAL 还是 NEGATIVE?边界模糊的样本准确率可能只有 80%。如果业务要求 ≥95%,要么加 Few-shot 示例,要么用 EmbeddingClassifier + 人工校验。

坑 3 · 分类是 LLM 任务,不是"思维链"

不要在 prompt 里写"先分析原因再判断" — 浪费 token 又慢。直接给指令 + 标签 + (可选 Few-shot),让它直接出答案。返回 Result<Sentiment> 还能拿到 token 用量。

坑 4 · EmbeddingTextClassifier 样例要"代表性强"

每类至少 5-10 个典型样例。如果只给"好"/"坏"两个词,模型会把"出色"判成负面(因为跟"坏"在向量空间近)。多给几个同义词变体。

坑 5 · 分类超 20 类 = LLM 也搞不定

LLM 一次能"记住"的标签数 ≈ 10-20。超过这个数(比如 100 个细分类目)准确率断崖下跌。要么二级分类(先大类别,再小类别),要么用专业微调模型。
