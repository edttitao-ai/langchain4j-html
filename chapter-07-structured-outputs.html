JSON Schema · POJO 映射

07Structured Outputs(结构化输出)

LLM 默认返回自由文本,你要写正则去抠 JSON。JsonSchema 告诉模型"按这个 schema 输出",LangChain4j 自动解析成你的 POJO。AI Service 模式下连 schema 都自动生成。

一句话定性:Person 是 record,interface 方法返回 Person —— LangChain4j 自动生成 Person 的 JSON Schema 发给模型,模型按 schema 输出 JSON,LangChain4j 反序列化成 Person 对象给你。零样板。

1. 业务场景

老板:"我们做简历解析,从一段自我介绍里抽出姓名、年龄、身高、婚否,塞到数据库。"

正则解析非结构化文本 = 噩梦。JSON Schema 让模型按规定字段输出,程序直接拿对象。

3 个真实场景

  • 简历/合同解析 — 一段非结构化文本 → POJO
  • AI 表单填写 — 用户口述 → 结构化字段
  • 批量信息抽取 — 1000 条新闻 → List<NewsItem>

2. 3 种实现方式(从可靠到不可靠)

方式可靠度适用
JSON Schema(厂商原生支持)⭐⭐⭐OpenAI / Gemini / Mistral / Bedrock / Ollama

3. 入门 Person record + PersonExtractor

AI Service 模式最简形态 —— 定义 record + interface,LangChain4j 全自动:

// 1. 定义 record(数据载体)
record Person(String name, int age, double height, boolean married) {}

// 2. 定义 interface(返回 Person)
interface PersonExtractor {
    Person extractPersonFrom(String text);
}

// 3. 配置 ChatModel 开启 JSON Schema
ChatModel chatModel = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-4o-mini")
        .supportedCapabilities(RESPONSE_FORMAT_JSON_SCHEMA)   // ⭐ 关键
        .strictJsonSchema(true)                              // ⭐ 关键
        .build();

// 4. 创建 extractor + 调用
PersonExtractor extractor = AiServices.create(PersonExtractor.class, chatModel);
Person p = extractor.extractPersonFrom("John is 42 years old...");
System.out.println(p.name());   // → "John"

⚠️ 关键开关:supportedCapabilities(RESPONSE_FORMAT_JSON_SCHEMA) + strictJsonSchema(true) 必须显式打开,默认是关闭的。开错 = 模型不按 schema 输出,反序列化失败。

4. 底层 API 写法(不用 AI Service)

如果用 ch01 的 ChatModel 底层 API,手动构造 ResponseFormat:

ResponseFormat responseFormat = ResponseFormat.builder()
        .type(JSON)
        .jsonSchema(JsonSchema.builder()
            .name("Person")                              // OpenAI 必填
            .rootElement(JsonObjectSchema.builder()
                .addStringProperty("name", "The person's name")
                .addIntegerProperty("age", "The person's age")
                .addNumberProperty("height", "Height in meters")
                .addBooleanProperty("married", "Marital status")
                .required("name", "age")
                .build())
            .build())
        .build();

ChatRequest request = ChatRequest.builder()
        .messages(UserMessage.from("John is 42 years old..."))
        .responseFormat(responseFormat)
        .build();

6. 实战:多态 Animal 抽取(sealed interface)

Java 17+ 的 sealed interface 天然支持多态抽取 —— LangChain4j 自动加 type 判别字段:

sealed interface Animal permits Dog, Cat {}
record Dog(String name, String breed) implements Animal {}
record Cat(String name, boolean indoor) implements Animal {}

interface AnimalExtractor {
    Animal extractAnimalFrom(String text);
}

// 模型输出:{"value":{"type":"Dog","name":"Rex","breed":"Labrador"}}
// LangChain4j 自动反序列化成 Dog 实例(不是 Animal!)

7. @Description 防幻觉

LLM 经常"瞎填"(姓名不知道就填 "John Doe")。用 @Description 给字段加示例:

@Description("a person")
record Person(
    @Description("person's first and last name, for example: John Doe") String name,
    @Description("person's age, for example: 42") int age,
    @Description("person's height in meters, for example: 1.78") double height,
    @Description("true if married, false otherwise") boolean married
) {}

8. 必填字段控制

默认所有字段 optional(LangChain4j 防 LLM 瞎填)。要必填用 @JsonProperty(required = true):

record Person(
    @JsonProperty(required = true) String name,    // 必填,缺了 LLM 会被强制重试
    String surname                                       // 可选,缺了默认 null
) {}

⚠️ Optional 字段的坑:基本类型(int / boolean)即使 optional,LLM 漏传时 LangChain4j 会用默认值(0 / false)。你以为"没填",其实是 0。设计 POJO 时:用包装类型 Integer / Boolean,让 null 真的能表示"没填"。

10. 避坑指南

坑 1 · 忘了开 supportedCapabilities + strictJsonSchema

OpenAI 默认不开 JSON Schema 模式。光写 strictJsonSchema(true) 不开 capabilities = 直接报错。两个开关必须一起写,且要 OpenAI 文档说支持该模型的对应模式。

坑 2 · 默认所有字段 optional = 大量 null

LangChain4j 默认所有字段 optional(防 LLM 瞎填,但代价是字段大量 null)。如果业务需要必填(如订单号),加 @JsonProperty(required = true)。

坑 3 · 枚举 strict 模式仍可能幻觉

strictJsonSchema(true) 对 string/integer 字段管用,但enum 字段仍可能被填"近似值"(如 enum 是 ["RED","GREEN","BLUE"],模型填 "PURPLE" 仍可能通过 schema 校验)。

坑 4 · 多态 anyOf 厂商支持差

JsonAnyOfSchema(多态)在 OpenAI 一些模型上不支持根级 anyOf。LangChain4j 用 {"value":{...}} 包装绕过,但这意味着你的 Java 代码反序列化时要 unwrap —— 实际是 LangChain4j 自动做的,你不用管,但要知道这件事。

坑 5 · 复杂 record 嵌套 = schema 无限大

递归 POJO(Person { List<Person> children })OpenAI 之外的厂商大多不支持。LangChain4j 会启动时直接报错给你,而不是运行时炸 —— 看启动日志。
