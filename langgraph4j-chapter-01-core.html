01 核心库(图工作流 3 要素 + 编译 + 同步/异步)

StateGraph · 状态/节点/边 · 编译配置 · 同步 execute + 异步 stream · RunnableConfig · 8 业务场景

一句话定性:LangGraph4j = 把代理工作流建模为图。3 核心组件 — State(状态:共享数据快照)+ Node(节点:AsyncNodeAction 函数)+ Edge(边:AsyncCommandAction 路由),支持循环工作流 + 状态随时间演化。节点和边类似函数,可以包含 LLM 调用或纯 Java 代码。

关键心智模型:节点执行操作,边指示下一步该做什么。真正的强大在于 LangGraph4j 如何管理 State 的演化。

1. 业务场景

老板:"咱们的 AI 客服是 '用户输入 → LLM → 工具 → LLM → 工具 → 回答' 这种多步循环,用 if-else 写死了 200 行,加个新工具要改 5 个地方。怎么办?"

解法:用 LangGraph4j 的 StateGraph 把工作流建模为图。每个步骤是Node(函数),步骤之间用 Edge(边)连接,State 是节点间共享的"数据快照"。新增工具 = 加 1 个 Node + 1 条 Edge,不动其他。

8 个 LangGraph4j 核心库能解决的事

  • 🔄 多步循环代理 — 工具调用 → LLM 判断 → 调工具 → 再判断,LangGraph4j 天然支持循环,不用 if-else 写死
  • 🔀 条件分支 — 用户问"退换货"走 A 流程,"物流查询"走 B 流程,用条件边 addConditionalEdges 路由
  • 👥 人机协作(HITL) — 节点执行前/后设置断点,等人工审核再继续(interruptBefore / interruptAfter)
  • 💾 会话状态持久化 — 客服 Bot 跟用户聊 10 轮,中间崩了重启能接上(检查点 + 线程 ID)
  • 📊 实时进度推送 — 用户看到"正在调工具...正在分析..."(stream() + UPDATES 模式)
  • 🧩 模块化子图 — "订单处理"和"支付"是独立子图,主图按需组合(对应 ch02 子图)
  • ⏸️ 取消 + 暂停 — 用户点了"取消"按钮,图立即停(对应 ch06 取消)
  • 📈 跨进程恢复 — 检查点存 Postgres,服务挂了重启,接上 threadId 继续跑(对应 ch07 检查点)

💡 什么时候不需要:单步 LLM 调用、纯单轮对话、简单 if-else 就够 —— 直接用 LangChain4j 即可。LangGraph4j 是"工作流有循环 + 状态演化 + 多个工具 + 持久化"的场景。

口诀:Node 干活(state in → update out),Edge 路由(state → next node),State 共享。必须 .compile() 才能用。流(stream)拿每步,执行(execute)拿终态。条件边 = addConditionalEdges("nodeA", router, mapping)。

2. 3 核心概念

LangGraph4j 的一切都围绕 3 件事:

概念类型作用
State 状态AgentState(用户定义)共享数据结构,表示应用当前快照。在节点间流动。
Node 节点AsyncNodeAction(函数式接口)编码代理逻辑。接收 State → 执行计算/副作用 → 返回 State 更新请求。
Edge 边AsyncCommandAction(函数式接口)根据当前 State 决定下一步。可以是条件分支或固定转换。也能请求更新 State(👀)。

Node 和 Edge 类似函数 —— 可以包含 LLM 调用,也可以是纯 Java 代码(计算/查询/IO)。

3. 第一个图:Hello World

3 步建图:定义 State → 加 Node + Edge → 编译。

// 1. 定义 State schema
public class State extends AgentState {
    public State(Map<String, Object> initData) {
        super(initData);
    }
    public Optional<String> input()   { return value("input"); }
    public Optional<String> results() { return value("results"); }
}

// 2. 定义 Node(纯 Java 函数)
AsyncNodeAction<State> myNode = node_async(state -> {
    System.out.println("In myNode: " + state.input().orElse(""));
    return Map.of("results", "Hello " + state.input().orElse(""));
});

AsyncNodeAction<State> myOtherNode = node_async(state -> state);

// 3. 建图 + 加 Node + 加 Edge + 编译
import static org.bsc.langgraph4j.StateGraph.START;
import static org.bsc.langgraph4j.StateGraph.END;

var graph = new StateGraph(State::new)
    .addNode("myNode", myNode)
    .addNode("myOtherNode", myOtherNode)
    .addEdge(START, "myNode")
    .addEdge("myNode", "myOtherNode")
    .addEdge("myOtherNode", END)
    .compile();   // ← ⚠️ 必须 .compile() 才能用

// 4. 同步执行
var config = RunnableConfig.builder().threadId("thread-1").build();
Map<String, Object> result = graph.execute(Map.of("input", "World"), config);
System.out.println(result);
// 输出:{input=World, results=Hello World}

关键 4 点:

  • StateGraph 主要图类,用用户定义的 State 参数化
  • START / END 是特殊节点(虚拟),分别代表"用户输入入口"和"终止"
  • addEdge(START, "myNode") = 入口点; addEdge("myOtherNode", END) = 出口
  • .compile() = 基本结构检查(孤立节点等)+ 运行时参数(checkpoint / 断点)

3.1 为什么必须 compile?

阶段做什么
建图前加 Node、Edge、State schema(声明式,还没校验)
.compile()基本检查(孤立节点、循环引用)+ 注入运行时参数(checkpoint、断点)
execute/stream图运行(Node 按 Edge 顺序执行,State 在节点间流动)

没 compile 直接 execute? → 抛异常。compile() 必须。

4. 编译配置(CompileConfig)

CompileConfig 控制图运行时行为:

var compileConfig = CompileConfig.builder()
    .checkpointSaver(mySaver)         // 持久化(后接 ch07)
    .recursionLimit(50)                // 最大递归深度(默认 25,防死循环)
    .interruptBefore("nodeA", "nodeB") // 节点执行前中断(HITL 审核)
    .interruptAfter("nodeC")           // 节点执行后中断(结果审核)
    .interruptBeforeEdge(true)         // 边评估前中断
    .releaseThread(true)               // 释放线程关联数据
    .graphId("my-graph-1")             // 图 ID(日志/监控)
    .build();

var graph = graphBuilder.compile(compileConfig);
属性类型默认说明
checkpointSaverBaseCheckpointSavernull持久化(HITL / 跨进程恢复)
interruptBeforeSet<String>空这些节点执行前暂停
interruptAfterSet<String>空这些节点执行后暂停
interruptBeforeEdgebooleanfalse边评估前中断(在分支前检查)
recursionLimitint25最大递归深度(防死循环)
releaseThreadbooleanfalse检查点释放线程数据
graphIdStringnull图 ID(RunnableConfig.graphId() 获取)

5. 2 种执行模式

5.1 同步执行(execute)

阻塞,等图跑完,直接拿最终 State:

var config = RunnableConfig.builder()
    .threadId("thread-1")
    .build();

Map<String, Object> result = graph.execute(inputs, config);
System.out.println(result);  // 最终状态

适合:短任务(< 1 秒)、不需要中间过程、API 同步响应。

5.2 异步流式(stream)

返回 AsyncGenerator,遍历每一步:

var config = RunnableConfig.builder()
    .threadId("thread-1")
    .streamMode(CompiledGraph.StreamMode.UPDATES)  // 只输出变化
    .build();

var generator = graph.stream(inputs, config);

for (var stepResult : generator) {
    System.out.println("Step executed: " + stepResult);
}

stream 4 大用途:

  1. 实时更新:监控中间状态("正在分析...正在调工具...")
  2. 实时反馈:每步给用户展示进度
  3. 调试:看 State 在整个执行过程的演化
  4. 中断处理:断点触发时拿到 InterruptionMetadata

5.3 2 种流模式对比

模式输出用途
VALUES(默认)每步后输出完整状态调试 / 看 State 演化全貌
UPDATES每步后只输出变化实时 UI 推送 / 减少数据传输

6. RunnableConfig(执行配置)

RunnableConfig 在图执行时传递运行时信息,节点和边可以访问(通过 AsyncNodeActionWithConfig / AsyncCommandAction):

var config = RunnableConfig.builder()
    .threadId("user-123")                                  // 线程 ID
    .streamMode(CompiledGraph.StreamMode.UPDATES)          // 流模式
    .putMetadata("userId", "user-123")                     // 自定义元数据
    .putMetadata("tenantId", "org-456")
    .putMetadata("llmModel", "gpt-4-turbo")
    .putMetadata("isVip", true)
    .build();

graph.stream(inputs, config);
属性类型说明
threadIdString线程/会话 ID(检查点持久化关键)
checkpointIdString特定检查点(从某点恢复,不是从头)
nextNodeString指定下一个节点(用于中断恢复)
streamModeStreamModeVALUES / UPDATES(默认 VALUES)
metadataMap<String, Object>自定义 KV(userId / tenantId / API key / 模型选择)

5 个保留元数据(LangGraph4j 内部用,不要覆盖):

  • LG4j_STUDIO_MDK(Boolean):Studio 集成标志
  • LG4j_NODE_ID(String):当前执行节点 ID
  • LG4j_GRAPH_PATH(GraphPath):嵌套子图路径
  • LG4j_GRAPH_ID(String):图 ID
  • LG4j_SUBGRAPH_UPDATE_DATA(Map):子图恢复内部用

6.1 节点中访问 RunnableConfig

// 用 AsyncNodeActionWithConfig 替代 AsyncNodeAction
AsyncNodeActionWithConfig<State> node = (state, config) -> {
    var threadId = config.threadId().orElse("default");
    String userId  = (String) config.metadata("userId").orElse("anonymous");
    String model   = (String) config.metadata("model").orElse("gpt-3.5");
    var graphId    = config.graphId();

    System.out.printf("执行: thread=%s user=%s model=%s%n",
        threadId, userId, model);

    return Map.of("result", "processed for " + userId);
};

6.2 条件边中访问 RunnableConfig

AsyncCommandAction<State> router = (state, config) -> {
    String userId = (String) config.metadata("userId").orElse("anonymous");
    // 根据运行时配置路由
    if ("premium-user".equals(userId)) {
        return "premium-path";
    } else {
        return "standard-path";
    }
};

6.3 修改已有 config

var updatedConfig = config.updateMetadata(Map.of("llmModel", "gpt-4"));

6.4 常见 5 用例

  • 用户上下文:userId / tenantId / orgId
  • 功能开关:feature flag 运行时启用/禁用
  • 模型选择:根据 metadata 选 gpt-4 / gpt-3.5
  • 日志/监控:graphId() + threadId() 关联
  • 会话恢复:threadId() 拿历史 + 恢复

7. GraphResult(类型安全的结果)

stream() 返回的 AsyncGenerator 元素是 Object。用 GraphResult 工具类安全识别:

GraphResult finalResult = GraphResult.from(generator);

if (finalResult.isEmpty()) {
    System.out.println("result is empty");
} else if (finalResult.isStateData()) {
    Map<String, Object> state = finalResult.asStateData();
    System.out.printf("完成: state=%s%n", state);
} else if (finalResult.isNodeOutput()) {
    NodeOutput<?> output = finalResult.asNodeOutput();
    System.out.printf("完成: node=%s%n", output.nodeId());
} else if (finalResult.isInterruptionMetadata()) {
    InterruptionMetadata<?> meta = finalResult.asInterruptionMetadata();
    System.out.printf("中断: %s%n", meta);
}

4 种结果类型:

类型说明
StateData(Map<String, Object>)状态快照(最常见)
NodeOutput节点执行详情(nodeId + state + 元数据)
InterruptionMetadata中断元数据(断点触发时)
BaseCheckpointSaver.Tag检查点标识
empty无结果

8. State(状态)与 Schema

State schema = Map<String, Channel<?>>,每个 key 对应 State 中的一项:

// 简单覆盖 reducer(默认):新值覆盖旧值
static class SimpleState extends AgentState {
    static Map<String, Channel<?>> SCHEMA = Map.of(
        "input",  Channel.of((oldVal, newVal) -> newVal),     // 覆盖
        "counter", Channel.of((oldVal, newVal) -> newVal)     // 覆盖
    );
}

// 累加 reducer(AppenderChannel):新值追加到 List
static class MessagesState extends AgentState {
    static Map<String, Channel<?>> SCHEMA = Map.of(
        "messages", Channels.appender(ArrayList::new)         // 累加
    );
}

var graphBuilder = new StateGraph<>(MessagesState.SCHEMA, MessagesState::new);

8.1 Reducer(减速器)

Reducer = 决定"节点更新如何应用到 State"。每个 key 有自己的 reducer 函数:

  • 不指定 → 默认覆盖(新值替换旧值)
  • AppenderChannel → 累加(新值追加到 List)
  • 自定义 → 自己写 lambda((oldVal, newVal) -> newVal.toUpperCase())

8.2 内置 Channel 速查

ChannelReducer 行为典型用途
Channel.of((o, n) -> n)覆盖单值字段(input / result)
Channels.appender(ArrayList::new)累加聊天消息列表 / 工具调用历史
Channels.appender(...).withRemoveBy(...)累加 + 可删除需要"删消息"的聊天
Channels.replaceAllWith(...)全部替换重置整个列表

8.3 AppenderChannel + RemoveByHash(实战)

var workflow = new StateGraph<>(MessagesState.SCHEMA, MessagesState::new)
    .addNode("agent_1", node_async(state -> Map.of("messages", "message1")))
    .addNode("agent_2", node_async(state -> Map.of("messages", List.of("message2", "message2.1"))))
    .addNode("agent_3", node_async(state -> Map.of(
        "messages", RemoveByHash.of("message2.1")  // ← 删 message2.1
    )))
    .addEdge(START, "agent_1")
    .addEdge("agent_1", "agent_2")
    .addEdge("agent_2", "agent_3")
    .addEdge("agent_3", END);

8.4 自定义 Reducer

// Reducer:新值转大写
static class MyState extends AgentState {
    static Map<String, Channel<?>> SCHEMA = Map.of(
        "property", Channel.<String>of((oldVal, newVal) -> newVal.toUpperCase())
    );
}

9. 4 种边(Edge)

类型方法何时用
普通边addEdge(from, to)A → B 固定转换
条件边addConditionalEdges(from, router, mapping)根据 State 路由(分支/终止)
入口点addEdge(START, node)图启动时第一个节点
条件入口点addConditionalEdges(START, router, mapping)根据 router 决定从哪个节点开始

9.1 普通边

graph.addEdge("nodeA", "nodeB");

9.2 条件边(关键!)

// router 返回字符串,EdgeMapping 决定字符串 → 哪个节点
graph.addConditionalEdges(
    "nodeA",
    routingFunction,                          // (state) -> "first" | "second"
    EdgeMapping.builder()
        .to("nodeB", "first")                 // 路由值"first" → 走 nodeB
        .to("nodeC", "second")                // 路由值"second" → 走 nodeC
        .build()
);

router 函数接收当前 State,返回字符串:(state) -> "first" | "second"。EdgeMapping 把 router 的输出映射到目标节点名。

9.3 入口点(START)

import static org.bsc.langgraph4j.StateGraph.START;

graph.addEdge(START, "nodeA");  // nodeA 是第一个跑的节点

9.4 条件入口点

import static org.bsc.langgraph4j.utils.CollectionsUtils.mapOf;

graph.addConditionalEdges(
    START,
    state -> {                                // 路由器
        if (state.containsKey("orderId")) return "order";
        return "general";
    },
    EdgeMapping.builder()
        .to("orderNode", "order")
        .to("generalNode", "general")
        .build()
);

10. 线程 + 检查点状态

线程 = 多个不同执行共享同一检查点(多租户聊天、独立会话)。

10.1 线程 ID 必传

// 用检查点时,threadId 必传
var config = RunnableConfig.builder()
    .threadId("user-session-a")
    .build();

graph.invoke(inputs, config);

10.2 3 个状态操作 API

方法作用
graph.getState(config)拿当前检查点的状态(包含 state + nextNodeId)
graph.getStateHistory(config)拿该线程所有历史检查点
graph.updateState(config, values, asNode)手动更新状态

10.3 updateState 3 要素

graph.updateState(
    config,                                  // threadId 在 config 里
    Map.of("messages", "人工新增消息"),         // values(走 reducer,不直接覆盖)
    "human_review"                            // asNode(模拟来自哪个节点)
);

3 要素:

  • config:必须含 threadId
  • values:走 reducer 处理(append 不直接覆盖,除非 reducer 是覆盖型)
  • asNode:模拟来自哪个节点(影响 reducer 链路);null = 上次更新状态的节点

11. 断点(中断)

图执行可以暂停在任意节点 —— HITL(人机协作) 的核心机制。

11.1 静态断点(编译时)

var compileConfig = CompileConfig.builder()
    .checkpointSaver(saver)        // ← 必须有 saver 才能中断后恢复
    .interruptBefore("tools")      // tools 节点执行前暂停
    .interruptAfter("llm")         // llm 节点执行后暂停
    .build();

11.2 动态断点(运行时)

实现 InterruptableAction<State> 接口:

public interface InterruptableAction<State extends AgentState> {
    Optional<InterruptionMetadata<State>> interrupt(
        String nodeId, State state, RunnableConfig config
    );
}

3 步行为:

  1. 图执行节点前检查是否实现 InterruptableAction
  2. 调 interrupt(...) 方法
  3. 返回非空 Optional → 暂停执行;返回空 → 正常执行

11.3 恢复执行

// 1. 第一次跑(可能遇到断点)
graph.stream(inputs, config);

// 2. 拿到 InterruptionMetadata,人工审核完,resume
graph.stream(GraphInput.resume(), config);              // 不传新数据
graph.stream(GraphInput.resume(Map.of("key", "value")), config);  // 传新数据

11.4 拿 InterruptionMetadata

var generator = app.stream(inputs);
for (var step : generator) { /* ... */ }

var finalResult = GraphResult.from(generator);
if (finalResult.isInterruptionMetadata()) {
    var meta = finalResult.asInterruptionMetadata();
    // 把 meta 发给前端 / 人工审核
}

13. 决策树(怎么用 LangGraph4j?)

14. 5 个避坑

⚠️ 坑 1:忘了 .compile() 直接 execute
症状:graph.execute(...) 抛异常或返回奇怪结果。
根因:compile() 是必须的(基本结构检查 + 运行时参数注入),没 compile 没法执行。
修法:建图最后一行必加 .compile()。
⚠️ 坑 2:用 if-else 写死了"循环代理"
症状:"LLM 调用 → 如果是工具调用就再调 LLM"用 while 循环 + if-else 写了 200 行,加新工具要改 5 处。
根因:没用 LangGraph4j 的循环边。
修法:用 addEdge("llm", "toolExecutor") + addConditionalEdges("toolExecutor", (state) -> state.get("shouldContinue") ? "llm" : END) 写循环。
⚠️ 坑 3:reducer 选错,状态没按预期演化
症状:用 Channel.of((o, n) -> n) 处理 messages,期望"累积聊天记录",结果每次都被新消息覆盖,只看到 1 条。
根因:默认 reducer 是覆盖,不是累加。
修法:消息/列表类用 Channels.appender(ArrayList::new)(累加);单值字段用 Channel.of((o, n) -> n)(覆盖)。
⚠️ 坑 4:用断点忘了 checkpointSaver
症状:interruptBefore("tools") 配了,图跑到 tools 节点挂住,resume 时状态丢了。
根因:没有 checkpointSaver,中断后无法恢复。
修法:断点 + checkpointSaver 必须配对(内存版 MemorySaver / Postgres 版见 ch07)。
⚠️ 坑 5:graph.execute() 阻塞太久 / stream() 忘了遍历
症状 1:graph.execute() 在长工作流上卡 30 秒,用户超时。
症状 2:graph.stream() 返回 generator 但没遍历,图根本没跑。
根因:execute 同步阻塞;stream 懒执行,必须消费 iterator 才会触发。
修法:
  • 长任务用 stream() + 前端 SSE / WebSocket 推每步进度
  • 短任务(< 1 秒)用 execute() 一次性拿结果
  • stream() 拿到 generator 必须立刻遍历(哪怕只要最终结果也要 for 一下)
