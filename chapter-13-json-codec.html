13JSON 编解码器(别碰,除非你真的需要)

Jackson 默认 + SPI 可换 + 5 业务场景 + ServiceLoader 机制

一句话定性:Jackson 默认 + JsonCodecFactory SPI(Java Service Provider Interface) + META-INF/services/ 声明式替换 = 99% 场景你不用碰这章。只有 Jackson 依赖冲突/自定义日期格式/多态序列化时才需要改。

1. 业务场景

老板:"咱们的 LLM Tools 输出用了 Jackson,但 JetBrains 插件市场报 ClassNotFoundException: com.fasterxml.jackson.databind.ObjectMapper。怎么让 LangChain4j 换成 Gson?"

解法:LangChain4j 把 JSON 序列化做成 SPI(Java Service Provider Interface)。你实现一个 JsonCodecFactory 接口,在 META-INF/services/dev.langchain4j.spi.json.JsonCodecFactory 文件里指明实现类,LangChain4j 会通过 ServiceLoader 自动加载它,代替默认 Jackson。

5 个 JSON Codec 能解决的事

  • 💥 依赖冲突 — IntelliJ/Android/某些受限沙箱环境里 Jackson 与宿主框架版本冲突,换成 Gson / Moshi / 自家实现
  • 📅 日期格式 — 默认 Jackson 序列化 LocalDateTime 是 timestamp 数组([2026,6,20,14,30]),某些 LLM 看不懂;改成 "2026-06-20T14:30"
  • 🎭 多态序列化 — Tool 参数是 Animal(接口),实际传入 Dog / Cat,加 @JsonTypeInfo 加类型字段让 LLM 看懂
  • 🔐 敏感字段 — 用户手机号/身份证在 JSON 输出时自动脱敏(***MASKED***),无需手动 toString
  • ⚡ 性能优化 — Jackson 默认启用所有模块,某些场景下关闭特性 / 改用 afterburner 模块可提速 30%+

💡 99% 场景你不用看这章:LangChain4j 内置的 JacksonJsonCodec(在 dev.langchain4j.internal 包)已经覆盖绝大多数场景。除非上面 5 条命中你,否则别动这章。

口诀:能用默认就用默认,SPI 改动是 last resort;改之前先看官方 internal 源码,改之后必须 5 场景回归测试。

2. 核心机制

└─────────────────────┬───────────────────────────────────┘
                      │
                      ▼

└─────────────────────────────────────────────────────────┘

2.1 什么是 SPI

SPI(Service Provider Interface) 是 Java 标准的服务发现机制(java.util.ServiceLoader),规范三件事:

  • 接口:服务接口(这里是 JsonCodecFactory)
  • 实现:你写一个类实现接口
  • 声明:在 META-INF/services/<接口全限定名> 文件里写实现类 FQDN

LangChain4j 用了 SPI 后:用户替换实现,不改 LangChain4j 任何代码,符合开闭原则。

2.2 LangChain4j 默认的 Jackson 实现

类位置作用
JsonCodecdev.langchain4j.spi.json编解码接口(serialize / deserialize)
JsonCodecFactorydev.langchain4j.spi.json工厂接口(create → JsonCodec)
JacksonJsonCodecdev.langchain4j.internalLangChain4j 自带的 Jackson 实现(默认)

⚠️ 注意:JacksonJsonCodec 在 internal 包 —— 官方忠告"这是内部使用",API 可能随时改。别直接 import 它(虽然能 import 到),正确做法是看它的源码作参考,自己实现 JsonCodecFactory。

3. 默认 Jackson 行为

LangChain4j 默认引入 langchain4j-core(传递依赖 jackson-databind)就自动用 Jackson。Tools 和 Structured Outputs 都依赖这个序列化器:

// pom.xml(默认就有)
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-core</artifactId>
    <version>1.11.8-beta19</version>
</dependency>
// 它传递依赖:
//   com.fasterxml.jackson.core:jackson-databind
//   com.fasterxml.jackson.datatype:jackson-datatype-jsr310

Tools 序列化示例(看默认行为):

// 你的 Tool 方法
public class BookingTools {
    @Tool
    public BookingStatus checkBooking(@P("bookingNumber") String bookingNumber) {
        return new BookingStatus(
            bookingNumber,
            LocalDateTime.of(2026, 6, 20, 14, 30),  // ← 默认 Jackson 序列化:
            "CONFIRMED"                              //    [2026,6,20,14,30] 数组
        );                                           //    不是 ISO 字符串!
    }
}

// LLM 看到的 JSON(Tools 传给 LLM 时):
// {"bookingNumber":"BK-001","bookingTime":[2026,6,20,14,30],"status":"CONFIRMED"}
//                                            ↑ LLM 看不懂这个格式

💡 这就是为什么要改:某些 LLM(尤其是小模型)看到数组时间会困惑,需要改成 "2026-06-20T14:30:00" 字符串。

4. 自定义步骤(3 步)

按官方文档的标准流程:

4.1 第 1 步:实现 JsonCodecFactory

// src/main/java/example/MyJsonCodecFactory.java
package example;

import dev.langchain4j.spi.json.JsonCodec;
import dev.langchain4j.spi.json.JsonCodecFactory;

public class MyJsonCodecFactory implements JsonCodecFactory {
    @Override
    public JsonCodec create() {
        return new MyJsonCodec();   // 自己实现 JsonCodec
    }
}

// JsonCodec 接口(简化)
public interface JsonCodec {
    String toJson(Object o);
    <T> T fromJson(String json, Class<T> type);
    <T> T fromJson(String json, TypeReference<T> typeRef);
}

4.2 第 2 步:实现 JsonCodec

这里我们用一个"包装 Jackson + 自定义配置"模式:不重新发明轮子,复用 Jackson 但调整 ObjectMapper:

// src/main/java/example/MyJsonCodec.java
package example;

import com.fasterxml.jackson.core.type.TypeReference;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.SerializationFeature;
import com.fasterxml.jackson.datatype.jsr310.JavaTimeModule;
import dev.langchain4j.spi.json.JsonCodec;

public class MyJsonCodec implements JsonCodec {

    private final ObjectMapper mapper;

    public MyJsonCodec() {
        this.mapper = new ObjectMapper()
            .registerModule(new JavaTimeModule())                          // LocalDateTime 序列化
            .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)     // 禁用时间戳数组
            .disable(SerializationFeature.FAIL_ON_EMPTY_BEANS)            // 空 bean 不报错
            .enable(SerializationFeature.INDENT_OUTPUT);                  // 调试时可读
    }

    @Override
    public String toJson(Object o) {
        try {
            return mapper.writeValueAsString(o);
        } catch (Exception e) {
            throw new RuntimeException("JSON 序列化失败", e);
        }
    }

    @Override
    public <T> T fromJson(String json, Class<T> type) {
        try {
            return mapper.readValue(json, type);
        } catch (Exception e) {
            throw new RuntimeException("JSON 反序列化失败", e);
        }
    }

    @Override
    public <T> T fromJson(String json, TypeReference<T> typeRef) {
        try {
            return mapper.readValue(json, typeRef);
        } catch (Exception e) {
            throw new RuntimeException("JSON 反序列化失败", e);
        }
    }
}

4.3 第 3 步:注册 SPI

在 src/main/resources/META-INF/services/ 下创建文件:

📁 src/main/resources/
└── 📁 META-INF/
    └── 📁 services/
        └── 📄 dev.langchain4j.spi.json.JsonCodecFactory

文件内容(就一行,你的工厂类 FQDN):
example.MyJsonCodecFactory

文件名 = 接口全限定名,文件内容 = 实现类 FQDN。Java 的 ServiceLoader.load(JsonCodecFactory.class) 会扫描所有 classpath 里的这个文件。

5. 实战:换 Gson(完整示例)

假设你的项目已经重度依赖 Gson(比如和 Android 共享代码),不想引 Jackson,可以全部换 Gson:

5.1 加 Gson 依赖

<!-- pom.xml -->
<dependency>
    <groupId>com.google.code.gson</groupId>
    <artifactId>gson</artifactId>
    <version>2.11.0</version>
</dependency>

5.2 实现 Gson 版 JsonCodec

// src/main/java/example/GsonJsonCodec.java
package example;

import com.google.gson.Gson;
import com.google.gson.GsonBuilder;
import com.google.gson.reflect.TypeToken;
import dev.langchain4j.spi.json.JsonCodec;

import java.lang.reflect.Type;

public class GsonJsonCodec implements JsonCodec {

    private final Gson gson;

    public GsonJsonCodec() {
        this.gson = new GsonBuilder()
            .setDateFormat("yyyy-MM-dd'T'HH:mm:ss")    // ISO 格式
            .serializeNulls()                          // null 字段也输出
            .create();
    }

    @Override
    public String toJson(Object o) {
        return gson.toJson(o);
    }

    @Override
    public <T> T fromJson(String json, Class<T> type) {
        return gson.fromJson(json, type);
    }

    @Override
    public <T> T fromJson(String json, TypeReference<T> typeRef) {
        // TypeReference → Type 转换
        Type type = typeRef.getType();
        return gson.fromJson(json, type);
    }
}

5.3 实现 Gson 版 Factory

// src/main/java/example/GsonJsonCodecFactory.java
package example;

import dev.langchain4j.spi.json.JsonCodec;
import dev.langchain4j.spi.json.JsonCodecFactory;

public class GsonJsonCodecFactory implements JsonCodecFactory {
    @Override
    public JsonCodec create() {
        return new GsonJsonCodec();
    }
}

5.4 注册 SPI

# src/main/resources/META-INF/services/dev.langchain4j.spi.json.JsonCodecFactory
example.GsonJsonCodecFactory

生效时机:启动时 ServiceLoader.load() 自动加载,无需任何代码调用。从此 LangChain4j 内部所有 JSON 操作走你的 Gson 实现。

6. 实战:自定义 Jackson(ObjectMapper 配置)

这是最常见场景 ——不替换 Jackson,只是改 Jackson 配置(默认 JacksonJsonCodec 没法改 ObjectMapper)。

6.1 业务诉求

  • LocalDateTime 输出 ISO 字符串(给 LLM 看)
  • null 字段不输出(减少 token 消耗)
  • BigDecimal 不变科学计数法
  • 未知字段不报错(LLM 可能加额外字段)

6.2 完整实现

// src/main/java/example/CustomJacksonCodec.java
package example;

import com.fasterxml.jackson.annotation.JsonInclude;
import com.fasterxml.jackson.core.type.TypeReference;
import com.fasterxml.jackson.databind.DeserializationFeature;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.PropertyNamingStrategies;
import com.fasterxml.jackson.databind.SerializationFeature;
import com.fasterxml.jackson.datatype.jsr310.JavaTimeModule;
import com.fasterxml.jackson.module.paramnames.ParameterNamesModule;
import dev.langchain4j.spi.json.JsonCodec;

import java.text.SimpleDateFormat;

public class CustomJacksonCodec implements JsonCodec {

    private final ObjectMapper mapper;

    public CustomJacksonCodec() {
        this.mapper = new ObjectMapper()
            // 1️⃣ 注册模块
            .registerModule(new JavaTimeModule())            // JSR-310(LocalDateTime 等)
            .registerModule(new ParameterNamesModule())     // 构造函数参数名(Java 8+)

            // 2️⃣ 时间格式
            .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)   // 不输出 timestamp 数组
            .setDateFormat(new SimpleDateFormat("yyyy-MM-dd'T'HH:mm:ss"))

            // 3️⃣ null 字段不输出(省 token)
            .setSerializationInclusion(JsonInclude.Include.NON_NULL)

            // 4️⃣ 兼容 LLM 加的额外字段
            .disable(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES)

            // 5️⃣ 大小写策略(LangChain4j 默认 camelCase,某些 LLM 输出 snake_case)
            .setPropertyNamingStrategy(PropertyNamingStrategies.LOWER_CAMEL_CASE)

            // 6️⃣ 空 bean 不报错
            .disable(SerializationFeature.FAIL_ON_EMPTY_BEANS);
    }

    @Override
    public String toJson(Object o) {
        try { return mapper.writeValueAsString(o); }
        catch (Exception e) { throw new RuntimeException("toJson 失败", e); }
    }

    @Override
    public <T> T fromJson(String json, Class<T> type) {
        try { return mapper.readValue(json, type); }
        catch (Exception e) { throw new RuntimeException("fromJson(Class) 失败", e); }
    }

    @Override
    public <T> T fromJson(String json, TypeReference<T> typeRef) {
        try { return mapper.readValue(json, typeRef); }
        catch (Exception e) { throw new RuntimeException("fromJson(TypeReference) 失败", e); }
    }
}

6 段配置对应 6 个真实痛点。直接 copy 这个就能解决 80% 场景。

7. 实战:多态序列化

Tools 参数如果是接口/抽象类,JSON 序列化必须保留类型信息,否则 LLM 调用时反序列化失败。

7.1 业务诉求

// Tool 方法签名
@Tool
public String processAnimal(Animal animal) { ... }

// 接口
public interface Animal {
    String name();
}

// 两个实现
public record Dog(String name, String breed) implements Animal {}
public record Cat(String name, boolean indoor) implements Animal {}

默认 Jackson 序列化:

// LLM 看到:
{"name":"旺财"}                          // ❌ 没有类型信息!
{"name":"小花","indoor":true}            // ❌ Jackson 自己猜

问题:LLM 调用时,LangChain4j 反序列化回 Animal,Jackson 不知道是 Dog 还是 Cat → 报错。

7.2 解法:加 @JsonTypeInfo

// Animal 接口
@JsonTypeInfo(
    use = JsonTypeInfo.Id.NAME,           // 用类名作为类型字段
    include = JsonTypeInfo.As.PROPERTY,
    property = "type"                     // 类型字段名叫 "type"
)
@JsonSubTypes({
    @JsonSubTypes.Type(value = Dog.class, name = "dog"),
    @JsonSubTypes.Type(value = Cat.class, name = "cat")
})
public interface Animal {
    String name();
}

序列化结果(LLM 能看懂):

{"type":"dog","name":"旺财","breed":"柴犬"}    // ✅ 完整类型信息
{"type":"cat","name":"小花","indoor":true}    // ✅

⚠️ 注意:@JsonTypeInfo 必须加在接口/抽象类上,不能加在实现类上。

7.3 自定义类型字段(改 name)

如果嫌 type="dog" 太长,可以自定义:

@JsonTypeInfo(
    use = JsonTypeInfo.Id.CUSTOM,         // 自定义
    property = "kind",
    visible = true
)
@JsonTypeIdResolver(MyAnimalResolver.class)  // 自定义类
public interface Animal { ... }

// 自定义解析器
public class MyAnimalResolver implements TypeIdResolver {
    @Override
    public String idFromValue(Object value) {
        if (value instanceof Dog) return "D";
        if (value instanceof Cat) return "C";
        return value.getClass().getSimpleName();
    }
    // ... 其他方法略
}

序列化:{"kind":"D","name":"旺财"} —— 短但更难读,生产环境用默认 NAME 即可。

9. 5 个避坑

⚠️ 坑 1:SPI 文件路径写错
症状:实现类写完,SPI 文件也建了,但 LangChain4j 仍然用默认 Jackson。
根因:META-INF/services/ 路径必须在 src/main/resources/ 下,拼成 META-INF/services/<接口全限定名>(没有 .class 后缀)。
修法:检查编译后的 JAR 里有没有这个文件:jar tf your.jar | grep META-INF/services。
⚠️ 坑 2:FQDN 拼写错误
症状:ServiceLoader 启动报 ServiceConfigurationError,整个 Spring Boot 启动失败。
根因:SPI 文件里写的类名跟实际类名不一致(常见大小写错、多空格、漏包名)。
修法:打开 JAR 里的 SPI 文件逐字核对 —— 一个空格都不能差。
⚠️ 坑 3:多 Jackson 版本冲突
症状:你自己用的 ObjectMapper 是 2.17,LangChain4j 内部用的是 2.15,你的自定义 Codec 调到 internal Jackson 类时抛 NoSuchMethodError。
根因:Maven 多模块依赖,不同 transitive 把 Jackson 拉成多个版本。
修法:<dependencyManagement> 显式锁定 Jackson 版本到所有模块一致。
⚠️ 坑 4:直接 import JacksonJsonCodec(internal 包)
症状:你代码里 import dev.langchain4j.internal.JacksonJsonCodec; 直接继承它,LangChain4j 下个版本改 internal 包,你的代码编译失败。
根因:internal 包按约定不保证 API 稳定。
修法:参考源码(看怎么配 ObjectMapper),但不要继承。自己实现 JsonCodec 接口。
⚠️ 坑 5:LocalDateTime 序列化 LLM 翻车
症状:Tool 返回包含 LocalDateTime,LLM 收到 [2026,6,20,14,30] 数组,LLM 小模型不理解,调用下一轮 Tools 时报错。
根因:Jackson 默认 WRITE_DATES_AS_TIMESTAMPS=true,序列化 JSR-310 类型为数组。
修法:自定义 Codec 里 disable(WRITE_DATES_AS_TIMESTAMPS) + registerModule(JavaTimeModule),输出 "2026-06-20T14:30:00"。
口诀:默认能不动就不动,SPI 路径精确到字符,不引 internal 包,版本冲突显式锁,日期格式必改 ISO。

11. 本章小结

  • 默认 Jackson:JacksonJsonCodec 在 internal 包,99% 场景你不用碰
  • SPI 替换三步:实现 JsonCodecFactory → 实现 JsonCodec → 写 META-INF/services/ 文件
  • 常见动机:依赖冲突 / 日期格式 / 多态序列化 / 敏感脱敏 / 性能优化
  • 多态关键:接口上加 @JsonTypeInfo,LLM 才能看懂 type="dog"
  • 5 避坑:SPI 路径 / FQDN 拼写 / Jackson 版本冲突 / 别引 internal 包 / 日期改 ISO
